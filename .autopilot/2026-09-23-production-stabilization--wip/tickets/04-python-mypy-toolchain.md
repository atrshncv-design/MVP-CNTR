# 04 — Совместимый Python/mypy toolchain

**Требования:** R20, R21. **После:** T03 baseline. **Зона:** backend toolchain и CI, только если проверка докажет необходимость.

## Контекст

`uv run mypy app` завершился с exit 2 до анализа приложения: `numpy/__init__.pyi:737: Type statement is only supported in Python 3.12 and greater`. Локальная среда Python 3.14.0, `pyproject.toml` задаёт mypy `python_version = "3.11"`, CI использует Python 3.11. Нельзя объявлять это дефектом кода приложения без отдельного доказательства.

## Задача исполнителю

1. Воспроизвести канонический `uv run mypy app` и определить точную причинную цепочку (версия Python, mypy, numpy/stub и режим поиска импортов). Не читать `.env`/ключи.
2. Сначала проверить решение без правки продукта: совместимый интерпретатор/конфигурацию из уже имеющихся зависимостей. Если исправление требует изменения пина, lock-файла или CI, вернуть конкретный вариант и impact оркестратору до правки.
3. Не подавлять ошибки через `ignore_errors`, исключение всего numpy или отключение strict. Цель — реальная проверка `app/` без syntax blocker.
4. Зафиксировать точные команды/exit codes; после устранения blocker — полный `uv run mypy app`, `uv run ruff check app tests infra/alerter scripts/udgu_ingest`, `uv run pytest -q` либо явно согласованный оркестратором эквивалент проверки.

## Приёмка

- Причина numpy-stub mismatch доказана, не угадана.
- Mypy анализирует `app/` и завершается exit 0 либо возвращает конкретные ошибки приложения отдельным finding; никакого ложного GREEN.
- Lock/CI меняются только при доказанной необходимости; production и секреты не затронуты.
- Оркестратор независимо повторяет mypy и regression, ревьюит diff, затем коммитит и пушит.

Исполнитель не меняет `.autopilot/**`, не коммитит и не пушит.
