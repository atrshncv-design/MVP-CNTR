# 24 — Ассистент по реестрам

**Требование:** R33; дополняет R16/R26. **После:** T03/T04, T08/T14 и зелёного локального baseline.

Проверить пользовательский путь ассистента реестров до backend `/chat/tuno`: видимый UI, авторизация, только разрешённые открытые поля, изоляция контура `tuno`, источники в ответе, честный отказ при пустом корпусе и fallback при недоступном провайдере. Сначала сопоставить существующий `/dashboard/ai-assistant` (сейчас вызывает общий `/chat`) и реестровые экраны с продуктовым требованием; не включать закрытые данные и не расширять перечень полей без решения владельца. Для подтверждённого разрыва написать failing regression, затем минимальное исправление и focused тесты. Live provider eval и новая модель — после обновления ключа владельцем; до этого BLOCKED. Исполнитель не меняет `.autopilot/**` и не коммитит.
