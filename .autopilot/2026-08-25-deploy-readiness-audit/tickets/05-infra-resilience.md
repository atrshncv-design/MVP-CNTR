## Что должно заработать

Production-контур проекта поднимается одной командой на этой машине и проходит все health/readiness-проверки. Устойчивость подтверждена делом, а не описанием: рестарты сервисов, поведение при недоступности реплики, резервная копия снимается и восстанавливается по штатным скриптам. Инструкция деплоя сверена с реальностью; список пустых секретов для сервера готов.

## Из брифа, дословно

> «должен подготовить этот проект к деплою на сервер»
> «критерии … устойчивости»

## Разделы спецификации

Истории 10, 14; Решения (локальная прод-проверка, необратимое — только пользователь).

## Чек-лист аудита

- `docker compose` prod: поднять с нуля, дождаться health/readiness всех сервисов (nginx, backend ×2, db primary/replica, minio, clamav, redis)
- Healthcheck/restart policy у каждого сервиса; поведение при `docker stop` реплики БД (чтение деградирует управляемо, запись живёт)
- `backup.sh` — снять бэкап; `restore.sh` — восстановить в чистое окружение и сверить данные
- nginx: заголовки безопасности, лимит тела запроса, TLS (self-signed локально ок), таймауты
- `deploy.sh`, `backend-entrypoint.sh`: идемпотентность, advisory lock миграций, читаемость вывода
- `.env.production.example`: полнота против реально читаемых переменных кода; список того, что пользователь должен заполнить перед сервером
- README-DEPLOY.md: сверить шаги с фактическим поведением

## Критерии приёмки

- [ ] Прод-контур поднят локально, все health/readiness зелёные (лог/вывод приложен к отчёту)
- [ ] Цикл backup → restore выполнен успешно, восстановленные данные свершись с исходными
- [ ] Находки устойчивости: исправлено в infra-конфигах (безопасное) или в реестре
- [ ] Список пустых секретов `.env.production` (только имена переменных) передан оркестратору для финального отчёта
- [ ] Docker-ресурсы: контур ОСТАВИТЬ ЗАПУЩЕННЫМ после проверок — он нужен таску 06 для нагрузочного прогона (прибрать можно только временные контейнеры восстановления)
