# Спецификация: пакет доделок продакшена

## Задача

Платформа уже на боевом сервере и открывается по ссылке, но часть витрин —
пустышки, часть механик спрятана флагами, треть каталога медалей неполучаема,
а с телефонов сайт открывается только через VPN. Заказчик хочет обсудить
каждый разрыв детально и закрыть их пакетом правок, а нагрузку прогнать после.

## Решение

После пакета: создание проектов доступно заказчику и исполнителю; публичные
витрины есть у проектов, исполнителей, организаций и НИОКТР с детальными
страницами и серверным поиском; подбор исполнителей включён в интерфейсе;
кнопки генерации ТЗ/паспорта/ТЭО на месте и работают; каталог медалей честен
(всё видимое — получаемо); сайт открывается с телефонов без VPN на своём
домене; нагрузочный гейт прогнан после всех правок.

## Решения по реализации

1. Витрины реестров строятся на существующем механизме витрины проектов (загрузка страниц, склейка, пустые состояния) — новую архитектуру не вводим. Почему: один компонент чинить дешевле трёх разных.
2. Детальные страницы — серверный рендер по slugs/номерам (проект id, организация ОГРН, НИОКТР регномер). Почему: ссылки должны открываться без входа и индексироваться.
3. Серверный поиск — параметры к существующим публичным ручкам, клиентский фильтр остаётся как ускорение поверх. Почему: искать по всей базе клиент не может.
4. Подбор включается снятием флага и переключением заглушки API-клиента на реальный вызов — экран уже написан. Почему: не дублируем готовое.
5. Генерация: кнопки в карточке проекта + серверный роут шаблонов вместо несуществующего (либо чиним роут, либо правим вызов — решает тикет). Почему: разрыв в одном месте.
6. Медали: выдача дописывается хуками на существующие события (создание проекта, верификации, организации); секретные скрываются флагом; отзыв — вызовом существующего сервиса отзыва. Почему: движок уже есть, не хватает вызовов.
7. Домен: покупка владельцем, выпуск сертификата тем же механизмом, переключение адресов в окружении, редирект со старого имени. Почему: причина мобильных блокировок — репутация wildcard-зоны, лечится только своим именем.
8. Нагрузка правится после функционала: мощности интерфейсу + тест, бьющий как живые люди (распределённые ключи/адреса), а не один робот. Почему: чинить то, что ещё двигается, — дважды платить.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `registry-ui` | публичные витрины и деталки | страницы `/projects /performers /customers /nioktr` + деталки | склейку страниц, клиентский фильтр |
| `registry-api` | публичные данные реестров | `GET /projects/registry /executors/* /nioktr*` + поиск | лимиты, сортировку по умолчанию |
| `project-create` | создание и публикация | `POST /projects`, `PUT /publish` | анкету УГТ, контрольные точки |
| `matching` | подбор исполнителей | `POST /match` | скоринг, LLM-реранк |
| `generation` | документы из шаблонов | `POST /projects/{id}/generate/{doc}` | подстановку, хранение черновиков |
| `achievements` | каталог и выдача | `GET /achievements/catalog /mine`, хуки выдачи | правила триггеров, отзыв |

Швы для тестов: публичные HTTP-ручки реестров, `POST /match`, генерация через API, выдача медалей через события. Проверки — через них, без чтения внутренностей.
