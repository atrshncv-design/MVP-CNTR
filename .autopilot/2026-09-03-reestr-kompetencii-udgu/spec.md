# Спецификация: Реестр компетенций УдГУ — формат выгрузки для реестра потенциала УР

## Задача

ЦНТР ведёт на платформе «Технозрелость» реестры компетенций региона (организации, исполнители, оборудование, патенты). Коллега Кашин (УдГУ) готов выгрузить данные университета, чтобы максимально показать компетенции, но не понимает — *что именно* перечислять и *в каком виде* отдавать. Просто сказать «выгрузи всё, что есть» — значит отправить человека на месяцы ручной работы (о чём пишет Денис Волегов). Попросить только «чистые» Excel-таблицы — потеряем сырые детали, которые университет уже хранит в разных системах (кафедры, научные заделы, миссия/фронтир, оборудование, патенты, услуги для МСП и т.п., причём перечень шире примеров).

Нужен баланс: дать Кашину понятное ТЗ и шаблон, который можно заполнить за дни, но не потерять «грязные» данные — принять их как есть и нормализовать уже на стороне ЦНТР.

## Решение

После сборки у ЦНТР и УдГУ появится:

1. **ТЗ-инструкция для Кашина** — один файл `README_УдГУ_выгрузка.md` + пример архива: что выгружать, в каких папках, какие колонки обязательны, а какие опциональны, как приложить сырые файлы.
2. **Физическая форма — архив по папкам по темам** (ZIP): `01_кафедры_и_лаборатории/`, `02_приоритеты_и_заделы/`, `03_миссия_фронтир/`, `04_оборудование/`, `05_РИД_патенты_публикации/`, `06_услуги_МСП/`, `07_люди_эксперты/` + расширяемые `08_...`, `09_...` — если у УдГУ есть ещё типы (пользователь уточнил: примеры не исчерпывающие). В корне — `00_опись.xlsx` (сводный Excel-шаблон 7 листов) + `00_опись.pdf` (человекочитаемая опись) + `raw/` для сырых дампов без обработки.
3. **Сводный Excel-шаблон как машиночитаемое ядро**: 7 листов (плюс шаблон для расширения). Каждый лист — таблица с фиксированными заголовками, валидацией и примером строки. Листы дублируют папки, но являются normalized view для импорта. Сырые файлы в папках — приложение, не требование к чистке.
4. **Пайплайн на стороне ЦНТР** (`scripts/udgu_ingest/`): принимает ZIP, валидирует структуру, читает Excel-ядро + индексирует сырые файлы, нормализует, дедуплицирует, отчитывается о полноте/пробелах и генерирует `udgu_import.json` в схеме платформы (Organization / competencies / Equipment / Patent). Ошибки — человекочитаемый отчёт, а не падение.
5. **Волновая стратегия**: Wave 1 (MVP 5–7 дней) — кафедры/лаборатории, люди, оборудование, патенты/публикации (то, что уже в ИС УдГУ). Wave 2 — миссия/фронтир, приоритеты/заделы, услуги для МСП и любые extra-типы. Шаблон и пайплайн не ломаются при добавлении листов/папок.

Ничего не требует от УдГУ чистки «в идеал» — «грязные» данные принимаются и обрабатываются у нас.

## Решения по реализации

**Стек и размещение:** Python 3.11+ (как backend), `openpyxl`/`pandas` для Excel, `pydantic` для схемы, `typer`/`click` для CLI, `pytest` для тестов. Код — `technozrelost-backend/scripts/udgu_ingest/` (CLI-пайплайн) + `technozrelost-backend/docs/udgu_template/` (шаблон и ТЗ). Без БД/миграций — импорт готовит JSON, заливка в реестры — отдельным шагом (out of scope для MVP). Почему так: не трогаем prod-схему, даём ЦНТР файл для ручной верификации до заливки.

**Шаблон Excel (`00_опись.xlsx`):**
- 7 листов: `01_кафедры_лаб`, `02_приоритеты_заделы`, `03_миссия_фронтир`, `04_оборудование`, `05_РИД`, `06_услуги_МСП`, `07_люди_эксперты`. Каждый с заголовком, примером, подсказками (комментарии), валидацией (выпадающие, формат дат).
- Лист `00_инструкция` — как заполнять, что обязательно.
- Лист `99_raw_опись` — таблица соответствий «файл в raw/ → сущность/строка».
- Почему Excel: Кашин и сотрудники умеют в него без обучения; CSV теряет валидацию; JSON требует ИТ.

**Архив ZIP:**
- Корень: `README_УдГУ_выгрузка.md`, `00_опись.xlsx`, `00_опись.pdf`, `raw/` (опционально), `01_.../` … `07_.../` + `08_...`.
- Имя по конвенции: `УдГУ_потенциалУР_YYYY-MM-DD.zip` (рекомендация, не строго).
- Почему архив по папкам: ответил пользователь (R25), удобно для человека и для пайплайна.

**JSON-схема (`schema/udgu_template.schema.json`):**
- Pydantic-модели: `UdguImport { university, departments[], priorities[], mission, equipment[], patents[], services[], people[], raw_refs[] }`.
- Каждое поле — с типом, `competencies: list[str]` как в платформе, `trl: int 1-9` опционально.
- Почему Pydantic: едино с backend.

**Пайплайн `ingest.py`:**
- Вход: `--zip` путь к архиву. Выход: `--out` папка с `udgu_import.json` + `report.md` + `report.json` + `warnings.log`.
- Шаги: 1) unzip + CRC, 2) найти `00_опись.xlsx` (по шаблону имени, fallback — любой .xlsx в корне), 3) прочитать листы → pydantic, 4) проиндексировать файлы в папках → `raw_refs`, 5) валидация (обязательные поля, дубли по названию/инвентарному), 6) отчёт: заполненность %, пустые разделы, ошибки по строкам, список raw-файлов.
- Ошибки: Wrong input — подробная строка/поле; Failure — CRC/нечитаемый Excel — не падает, пишет в отчёт; Empty — пустой лист валиден; Interruption — повторный запуск идемпотентен (выходные файлы перезаписываются); Growth — до 10k строк/лист, дальше warning; Boundaries — только чтение архива, нет записи в БД.
- Почему CLI а не сервис: MVP должен работать оффлайн у ЦНТР без деплоя.

**Маппинг на платформу (R20):**
- Таблица в ТЗ: как поля шаблона ложатся на `organizations.competencies`, `equipment`, `patents` и т.д. Без кода миграции — только документация.

**Валидация:**
- Hash для дедупликации по `(тип + нормализованное название + год)`.
- B-Tree логика для диапазонов дат/годов (валидация, не индекс БД).

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|--------|---------|------------|--------|
| `udgu-template` | Excel-шаблон, JSON-схема, ТЗ-инструкция, пример архива | `00_опись.xlsx`, `schema/*.json`, `README_УдГУ_выгрузка.md`, `example/УдГУ_...zip` | вёрстку Excel, детали валидации ячеек |
| `udgu-ingest` | CLI-пайплайн normalize+validate+report | `ingest.py --zip --out`, `udgu_import.json` (схема), `report.md/json` | парсинг openpyxl, нормализацию имён папок/листов, логику дедупликации |
| `udgu-mapping` | Документация маппинга на реестры платформы | таблица маппинга в ТЗ, `mapping.md` | детали ORM платформы |

Швы для тестов — публичные выходы модулей:
- `udgu-template`: наличие файлов + валидность Excel (открывается, листы на месте) + JSON-схема валидна.
- `udgu-ingest`: `ingest.py` как чёрный ящик — на вход ZIP, на выход JSON+отчёт, поведение проверяется через файловую систему, без БД.

Предпочтительный шов — `udgu-ingest` CLI (один). Число швов минимально.

## Вне рамок

| Требование | Почему не сейчас |
|------------|------------------|
| Прямая заливка в БД платформы (миграция/alembic) | импорт требует ручной верификации ЦНТР; заливка — следующий заход после утверждения json |
| Веб-UI загрузки архива | CLI покрывает MVP; UI — когда поток станет регулярным |
| OCR/извлечение текста из PDF сырых файлов | сырые файлы индексируются как ссылки; глубокий парсинг — Wave3 |
| LLM-обогащение описаний компетенций | `A`-идея, требует `LLM_API_KEY`, вне MVP |
| Автодедупликация межвузовых сущностей | только внутри УдГУ; кросс-вуз — после накопления 2+ выгрузок |

## Открытые места

Заполнителей (`placeholder`) нет — все поля имеют пример или помечены опциональными. Если УдГУ не имеет данных по листу — строка «нет данных» + пустая папка — валидно.

Переменные окружения не требуются. При использовании как библиотеки нужен `python3.11+` и `pip`.
