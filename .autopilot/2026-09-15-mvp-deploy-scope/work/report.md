# MVP-деплой «Технозрелости»: доказуемый минимум, пакеты, блокеры

Статус прошлого отчёта (4 vCPU / 16 ГБ / 120 ГБ, «без Replica» как ужатие)
и оценки `docs/СЕРВЕР-ТРЕБОВАНИЯ.md` (4 vCPU / 12 ГБ / 500 ГБ, Replica,
2 реплики backend) — **отозваны как недоказуемые**. Ниже — только числа
с трассировкой к замеру, лимиту или ответу. Секреты — только именами.

## 1. Доказуемый минимум: 6 vCPU / 11 ГиБ RAM / 150 ГБ SSD

| Ресурс | Минимум | Трассировка |
|---|---|---|
| vCPU | 6 | сумма лимитов CPU в `infra/docker-compose.prod.yml` = 6.0; гейт `infra/preflight.py` (`MIN_CPUS=6`) отклоняет слабее до сборки |
| RAM | 11 ГиБ | сумма лимитов памяти = 7680M = 7.5 ГиБ ≤ 8 ГиБ (`MEM_BUDGET_MIB=8192`); остаток ~3.5 ГиБ — ОС, Docker, пик сборки; гейт `MIN_MEM_GIB=11`; факт сервера — 12 ГБ (ответ 2026-09-16) ≈ 11.2 ГиБ |
| Диск | 150 ГБ SSD | 100 МБ новых файлов/день (G15) × 365 ≈ 37 ГБ/год без удаления (G16) + 7 полных снапшотов + WAL + мониторинг + образы; гейт требует ≥60 ГБ свободно (`MIN_DISK_FREE_GB=60`) |
| Лимиты | CPU ≤6.0, RAM ≤8 ГиБ | `preflight.py`: превышение бюджета = отказ до сборки; Redis `maxmemory 200mb` внутри лимита 256M, Prometheus ретеншн `15d`/`10GB` |

Состав лимитов (таблица «Ресурсный конверт P1» в `infra/README-DEPLOY.md`,
все значения — из `docker-compose.prod.yml`): PG Primary 1.0/1536M,
backend ×1 1.0/1536M, ClamAV 1.0/2G (1–2 ГиБ по проекту; замер 7 МиБ снят
с нездорового демона и нерепрезентативен — G42), frontend 0.75/768M,
MinIO 0.5/384M, Redis 0.25/256M, Prometheus 0.5/384M, Grafana 0.25/256M,
nginx 0.25/128M, alerter 0.1/128M, backup-timer 0.25/128M,
wal-offsite 0.15/128M.

Проверенные измерения (ответы после интервью, не цели): архив всего
репозитория 22 300 794 байта (~21.3 МиБ), backend+frontend 18 394 405 байт
(~17.5 МиБ) — G23; backend-образ ~682 МБ распакованным (Python, зависимости,
seed-файлы, не данные БД) — G24; неполный локальный стенд ~1 499 МиБ
контейнеров + 86 МиБ локальных frontend/backend — G25 (полный контур требует
нагрузочного замера, см. §4).

## 2. Состав пакетов P1/P2/P3

- **P1 — сервер и облегчённый контур (этот отчёт).** Один узел, один
  PostgreSQL Primary, один backend — без Replica по проекту (не «ужатие»,
  а решение: без SLA, окно обслуживания в `infra/RUNBOOK-DATA.md`).
  Обязательны Redis, MinIO, ClamAV, nginx, frontend, мониторинг, ежедневные
  локальные бэкапы. Временный адрес `<ipv4>.sslip.io` + ACME TLS (таск 07).
- **P2 — инфоконтур + весь ЛК + AI/RAG.** Главная/о платформе/методология/
  уровни/roadmap/новости (пустые честно)/вход/регистрация; вход и
  саморегистрация только базовых ролей (привилегированные выдаёт персонал
  `cntr_admin`/`cntr_manager`); все восемь кабинетов; жизненный цикл,
  профили/команды, файлы до 25 МБ с ClamAV, уведомления; AI-ассистент и
  RAG-поиск только по 15 `ГОСТ*.pdf`, ключ `OPENCODE_API_KEY` вводит владелец.
  Matching и публичные реестры скрыты (навигация, роуты, API-клиент).
- **P3 — публичные реестры.** Витрина + реестры после приёмки P2 под
  нагрузкой и наполнения проверенными данными (отдельный гейт).

## 3. Нагрузка G47: harness готов, замер — за оператором

Пороги (бриф 2026-09-16): ≥99% успеха, API p95 ≤1с, страницы p95 ≤2с,
RAM <80% при 50 concurrent (G03 «20–50»). Harness
`infra/acceptance_load.py` (stdlib, exit 0/1/2) + тесты
`tests/test_acceptance.py` (6 passed против локального стаба).
Команда оператору против Beget — `infra/README-ACCEPTANCE.md` §1.
**Фактический прогон на 50 concurrent не выполнен** (исполнитель не ходит
на живой сервер): критерий открыт до операторского замера с PASS.

## 4. Бэкапы G43: локально доказуемо; offsite G44 — блокер

Ежедневный полный снапшот (pg_dump + pg_basebackup + зеркало MinIO +
SHA256SUMS, `infra/backup.sh`), restore только в пустую БД с проверкой
сумм до изменений (`infra/restore.sh`), PITR-репетиция
`scripts/rehearse_pitr.sh`. Процедура репетиции — `README-ACCEPTANCE.md` §2.
Решение таска 10: **retention снижен 14 → 7** (`BACKUP_KEEP=7` везде):
каждый снапшот — полная копия, 14 копий бюджет 150 ГБ («3–7 снапшотов»,
Решения §4) не переживёт; RPO «до суток» (G43) сохраняется.
Offsite отсутствует (ответ «Пока нет», G44) — хранилище не импровизируется,
прод-RPO/RTO недоказуемы: боевой блокер.

## 5. Алерты G45: dry-run без секретов; живая доставка — за владельцем

`infra/acceptance_alert_dryrun.py` рендерит синтетический алерт без сети
и без значений секретов (exit 0) + `alerter.py --self-check`. Чек-лист ввода
`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` владельцем и живая проверка
ALERT→RECOVERY — `README-ACCEPTANCE.md` §3. До выполнения чек-листа
доставка считается недоказанной: боевой блокер «секреты владельца».

## 6. Боевые блокеры (без закрытия — нет боевых ПДн)

1. Документы ПДн не утверждены (G21: «Позже добавим — сейчас прототип») —
   регистрация с реальными ПДн заблокирована.
2. Offsite-хранилище отсутствует (G44) — катастрофоустойчивость не заявлена.
3. Секреты не введены: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
   `OPENCODE_API_KEY` (имена; значений нет нигде) — алерты и AI недоказаны.
4. Сменить root-пароль в панели Beget (раскрыт в переписке, правилом
   секретов запрещён к использованию) + удалить файл доступов из worktree.
5. Операторские замеры не выполнены: нагрузка §3, TLS-выпуск, живая
   проверка алертов, restore-репетиция на прод-объёме.
