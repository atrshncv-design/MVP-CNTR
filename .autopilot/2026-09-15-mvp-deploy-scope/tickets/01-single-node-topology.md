## Что должно заработать

Production-контур собирается на одном узле: один PostgreSQL Primary, один backend, без Replica и без второй реплики backend. Чтение реестров идёт в Primary. Production-БД стартует чистой — только справочники и утверждённый контент, без демопользователей и демопроектов.

> «Чистая БД»

## Разделы спецификации

Истории 1–2, 25–27, 39; Решения §2–§3; Швы `infra-single`.

## Критерии приёмки

- [ ] В production-определении нет сервиса Replica; работает ровно один backend
- [ ] `GET /api/v1/ready` возвращает 200: Primary `ok`, Replica `not_configured`
- [ ] Чтение реестров работает через Primary без ошибок записи
- [ ] Нет висячего слота репликации и проверок, требующих Replica
- [ ] Алертер не показывает Replica-предупреждений на одноузловом контуре
- [ ] Обновление не оставляет orphan-контейнеров Replica
- [ ] Секреты только именами; значений нет в логах и файлах
