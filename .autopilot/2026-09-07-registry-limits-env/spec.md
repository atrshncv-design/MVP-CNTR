# Спецификация: Лимиты реестра в env

## Задача

Три лимита реестра остались модульными константами, хотя их сосед уже живёт в настройках. Владелец стенда не может крутить их без правок кода — последний хвост прохода по конфигам.

## Решение

После прогона все четыре лимита реестра читаются из окружения с теми же дефолтами, имена задокументированы, сюита зелёная, поведение побитово то же.

## Пользовательские истории

| # | Метка | История | Приёмка |
|---|-------|---------|---------|
| 1 | R01 | Как владелец стенда, я задаю лимиты реестра через окружение, чтобы не править код | значения из env подхватываются, без env — дефолты |
| 2 | R02i | …и поведение не меняется | дефолты 10000/60.0/5000, тесты лимитов зелёные |
| 3 | R03i | …и ничего не ломается | сюита бэкенда зелёная, шов теста лимита жив |

## Решения по реализации

- Имена — по конвенции прошлого прогона: `REGISTRY_AUTH_LIMIT`, `REGISTRY_WINDOW_SECONDS`, `REGISTRY_MAX_ENTRIES`. Почему так: рядом уже живёт `REGISTRY_ANON_LIMIT`.
- Только имена в `.env.example`, без значений. Почему так: секретов/значений в пример не кладём.
- Типы — как у констант (int, float, int). Почему так: поведение то же, включая вещественное окно.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `settings` | лимиты реестра | `settings.registry_auth_limit / registry_window_seconds / registry_max_entries` | парсинг окружения, дефолты |

Шов: чтение лимитов из настроек + существующий тест лимита реестра + зелёная сюита.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| EN-ревью формулировок | ждёт пользователя, второй пункт остатка |
| P2 (палитра, дубль словарей, логи) | гигиена, осознанно не берём |
