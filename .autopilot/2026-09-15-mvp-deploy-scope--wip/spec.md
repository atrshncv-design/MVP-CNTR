# Спецификация: полный деплой MVP тремя пакетами

## Задача

Владелец готовит платформу «Технозрелость» к публичному MVP и хочет знать: какой минимум мощностей нужен под фактический сервер, что реально публикуется в первом релизе, а что честно откладывается. Предыдущая оценка мощностей отозвана как недоказуемая; новая считается только от ответов пользователя, замеров кода и серверного аудита.

## Решение

Три независимо принимаемых пакета. Каждый следующий не начинается, пока предыдущий не прошёл свои приёмки.

- **P1 — сервер и облегчённая инфраструктура.** Один узел, один PostgreSQL Primary, один backend, без Replica. Обязательны Redis, MinIO, ClamAV, nginx, frontend, базовый мониторинг и ежедневные локальные бэкапы. Временный адрес через sslip.io с доверенным TLS.
- **P2 — инфоконтур + весь ЛК + AI-ассистент/RAG.** Публичный инфоконтур, вход и саморегистрация только базовых ролей, все восемь ролевых кабинетов, жизненный цикл проекта, профили и команды, файлы и уведомления, достижения пустыми, новости с пустым состоянием. AI-ассистент и RAG-поиск только по корпусу ГОСТов через внешний OpenAI-совместимый провайдер, без ПДн и данных проектов. Matching скрыт.
- **P3 — публичные реестры.** Открытие витрины и реестров после проверки P2 под нагрузкой и наполнения проверенными данными.

Фактический боевой запуск с реальными ПДн заблокирован до трёх внешних гейтов владельца: утверждённые документы по ПДн, offsite-хранилище бэкапов, ввод секретов Telegram и LLM вне переписки.

## Решения по реализации

- Пакеты идут строго P1 → P2 → P3. Почему так: каждый следующий опирается на приёмку предыдущего.
- P1 — один узел: один PostgreSQL Primary, один backend, без Replica и без второй реплики backend. Почему так: сервер 6 vCPU / 11 ГиБ, SLA не требуется, чтение идёт в Primary.
- Суммарный жёсткий лимит контейнеров — не выше 8 ГиБ, остальное ОС, Docker и сборке. Почему так: иначе 11 ГиБ уйдут в OOM на пике.
- ClamAV планируется как 1–2 ГиБ. Почему так: локальный замер 7 МиБ снят с нездорового демона и нерепрезентативен.
- Диск 150 ГБ: данные, 3–7 локальных снапшотов, WAL, мониторинг, образы и кэш сборки в одном бюджете со счётчиком свободного места. Почему так: RPO 24 часа без offsite, 14 полных копий диск не переживёт.
- TLS — техническое имя на базе публичного IPv4 через sslip.io, выпуск через ACME, автообновление и редирект HTTP→HTTPS. Почему так: домена нет, а авторизация и ПДн по HTTP недопустимы.
- SSH уже защищён: парольный вход отключён, вход root только по установленному ключу. Почему так: пароль был раскрыт, сервер уже сканируют.
- P2 открывает инфоконтур, вход, саморегистрацию базовых ролей и все восемь кабинетов. Почему так: так утверждены границы релиза.
- Привилегированные роли выдают `cntr_admin` и `cntr_manager`. Почему так: прямое решение владельца.
- Публичные реестры и matching скрыты в P2 на уровне навигации, роутов и API-клиента. Почему так: иначе «отложено» останется только на словах.
- Email-подтверждения и восстановления нет; сброс через персонал. Почему так: SMTP нет, владелец принял риск.
- Новости и достижения показываются с честными пустыми состояниями. Почему так: БД чистая, врать нечем.
- Автоудаления документов нет; порог расширения диска — часть мониторинга. Почему так: хранение бессрочное.
- AI — только AI-ассистент и RAG-поиск; matching и генерация отчётов позже. Почему так: так выбран состав, отчётного контура в коде нет.
- Провайдер OpenCode Go подключается как OpenAI-совместимый endpoint; переменная ключа маппится в серверные настройки без значения в репо. Почему так: ключ есть у владельца, в переписку и git ему нельзя.
- Внешнему AI разрешены только фрагменты корпуса ГОСТов и обезличенный вопрос. Почему так: провайдер внешний и глобальный.
- Корпус — 15 `ГОСТ*.pdf` из чистой папки загрузок; импорт идёт через хеш-манифест, исходники в git не коммитятся. Почему так: в проекте лежат старые повреждённые копии и посторонние документы.
- Секреты только именами: серверные, Telegram, LLM. Почему так: правило секретов, значений в отчётах и тикетах нет.
- Проверенные измерения (ответы на вопросы интервью, не цели сборки): архив всего репозитория ~21,3 МиБ, архив backend+frontend ~17,5 МиБ; backend-образ ~682 МБ распакованным — это Python, зависимости и seed-файлы, а не данные БД; неполный локальный стенд занимает ~1,55 ГиБ RAM, полный контур требует отдельного нагрузочного замера. Почему здесь: эти цифры уже выданы пользователю, спецификация фиксирует их как факты.
- Детализация сверх брифа и её родители: лимит файлов 25 МБ → G14; ответы AI/RAG с цитатами → G53/G54; 15 `ГОСТ*.pdf`, хеш-манифест, запрет коммита исходников → G50/G58; сброс пароля через персонал → G39; идентификаторы `cntr_admin`/`cntr_manager` → G46. Почему так: всё это — существующее поведение кода или прямое уточнение требования, а не новые возможности.
- Боевые ПДн заблокированы до документов ПДн, offsite-хранилища и ввода секретов владельцем. Почему так: иначе запуск нарушит собственные гейты.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `infra-single` | одноузловой контур, лимиты, TLS, бэкапы, мониторинг | готовность `/ready`, публичный HTTPS, свежесть бэкапа | репликацию, число реплик, ACME-детали |
| `release-p2` | инфоконтур, ЛК, роли, gating реестров и matching | страницы, кабинеты, ролевые действия | скрытые маршруты, внутренние флаги |
| `ai-rag` | корпус ГОСТов, импорт, поиск, чат с цитатами | ответ с источниками, поисковые фрагменты | промпты, чанки, ключ провайдера |
| `release-p3` | публичные реестры и витрина | анонимное чтение проверенных данных | внутренние очереди модерации |
| `acceptance` | нагрузочные и боевые гейты | вердикт pass/fail по каждому пакету | сценарии нагрузки внутри |

Швы для тестов — публичные границы продукта: `GET /api/v1/health`, `GET /api/v1/ready`, публичные страницы по HTTPS, вход и саморегистрация базовых ролей, ролевые кабинеты, загрузка файла с антивирусом, SSE по ticket, RAG-поиск и чат с цитатами, свежесть бэкапа, доставка алерта. Новых швов не вводим.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| G28, G29, G31 — использование раскрытого пароля root | запрещено правилом секретов; удалённый пароль уже отключён, сам пароль сменить в панели |
| Replica, вторая реплика backend, HA, второй узел | один узел без SLA; вернуть при росте, пиле Primary или требовании 99.9% |
| Matching, генерация отчётов | не выбраны в состав; matching скрыт, отчётного контура нет |
| Постоянный домен | временный sslip.io; домен следующим шагом |
| Offsite-хранилище | отсутствует; до него только временные локальные копии |
| Подтверждение email и автовосстановление | SMTP нет; ручная процедура персонала |
| Закрытый контур, локальный LLM | внешний провайдер допустим для пилота; вернуть по требованию заказчика |
| Полный мониторинг сверх базового | базовая видимость сейчас, тонкая настройка после нагрузки |

## Открытые места

Placeholder-строк в манифесте нет. Внешние действия владельца, без которых боевое открытие заблокировано:

- сменить пароль root в панели после раскрытия;
- удалить файл доступов из worktree;
- утвердить документы по ПДн;
- создать S3-совместимое хранилище в облаке РФ;
- ввести секреты Telegram и LLM вне переписки;
- передать точное имя временного хоста и подтвердить DNS.
