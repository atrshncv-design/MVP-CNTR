# 04 — SSE по одноразовому ticket вместо токена в URL

**Требования:** R04i (история 8)
**Blocked by:** —
**Зона:** `backend/realtime`, `frontend/notify`, `infra/nginx`
**Волна:** 1
**Status:** ready

## Что должно заработать

Авторизованный POST выпускает короткоживущий одноразовый ticket; стрим
открывается по ticket в query; access-токен в URL запрещён; query стрима
исключён из access-лога; фронт ходит по новому контракту с fallback на polling.

## Из брифа, дословно

> составь спеку и тикеты для внесения правок
> «Всё + приоритеты»: спека покрывает все подтверждённые находки; таски — на Blocker/Critical/High/CI (Дополнения 2026-09-08)

## Разделы спецификации

История 8, Решение §4, Границы `realtime`.

## Критерии приёмки

- [ ] Контракт: `POST /notifications/sse-ticket -> {ticket}`, `GET /notifications/stream?ticket=`; TTL ~30с, одноразовое использование, повтор → отказ
- [ ] В access-логе балансировщика нет `access_token=` после открытия стрима
- [ ] Фронт получает события через ticket; при недоступности — polling без спама
- [ ] Просроченный/использованный ticket не открывает чужой поток
- [ ] Тест на шве HTTP покрывает выпуск, использование, повтор и лог
