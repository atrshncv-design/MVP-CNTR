# 06 — Атомарная ротация refresh-токенов

**Требования:** R05i (история 10)
**Blocked by:** 03
**Зона:** `backend/auth`
**Волна:** 2
**Status:** ready

## Что должно заработать

Ротация — одним атомарным UPDATE с условием «ещё не отозван»: два
параллельных refresh одним токеном дают один 200 и один 401; повтор
использования отозванного отзывает семью.

## Из брифа, дословно

> составь спеку и тикеты для внесения правок
> «Всё + приоритеты»: спека покрывает все подтверждённые находки; таски — на Blocker/Critical/High/CI (Дополнения 2026-09-08)

## Разделы спецификации

История 10, Решение §6, Границы `auth`.

## Критерии приёмки

- [ ] Два параллельных refresh одним токеном: один 200, второй 401
- [ ] Reuse отозванного токена отзывает семью и отклоняется
- [ ] Обычный refresh/round-trip пользователя не ломается (регрессия)
- [ ] Тест на шве HTTP покрывает гонку конкурентными запросами
