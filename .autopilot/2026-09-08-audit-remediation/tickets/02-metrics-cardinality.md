# 02 — Метрики с ограниченной кардинальностью

**Требования:** R03i (история 5)
**Blocked by:** —
**Зона:** `backend/observe`
**Волна:** 1
**Status:** ready

## Что должно заработать

Карта роутов для метрик строится после подключения всех роутеров, в метки
попадают шаблоны путей, а не сырые URL; значения меток экранируются;
несопоставленные пути складываются в одну bounded-метку.

## Из брифа, дословно

> составь спеку и тикеты для внесения правок
> «Всё + приоритеты»: спека покрывает все подтверждённые находки; таски — на Blocker/Critical/High/CI (Дополнения 2026-09-08)

## Разделы спецификации

История 5, Решения §2, §10, Границы `infra-observe`.

## Критерии приёмки

- [ ] 1000 запросов с уникальными ID не растят число серий сверх числа роутов
- [ ] Путь с кавычкой/бэкслэшем не ломает exposition `/metrics` до рестарта
- [ ] Дашборды считают среднее по cumulative-счётчикам корректно после окна сэмплов
- [ ] Две реплики скрапятся как отдельные инстансы, агрегаты сходятся
- [ ] Тест на шве HTTP покрывает кардинальность и экранирование
