# 03 — Документы для заказчика: требования к серверу и импортозамещение

**Требования:** R05, R06
**Blocked by:** —
**Зона:** `docs/`
**Волна:** 1
**Status:** ready

## Что должно заработать

Две одностраничные «рабочие лошадки», которые CTO отправляет заказчику и использует сам,
когда появится доступ к серверу: спецификация требований к серверу (чтобы машина приехала
без сюрпризов) и честная таблица импортозамещения (что в стеке мешает требованию отечественного
ПО и чем заменяется, если требование включат).

## Из брифа, дословно

> «техтребования к серверу заказчика (одностраничная спецификация: ОС, Docker, CPU/RAM/disk, исходящий доступ, их бэкапы)»
> «оценку текущего стека на импортозамещение»

## Разделы спецификации

Истории 8–9; Модуль docs/customer.

## Критерии приёмки

- [ ] `docs/СЕРВЕР-ТРЕБОВАНИЯ.md`: ОС, версии Docker/Compose, CPU/RAM/disk (с расчётом под ClamAV+PG+MinIO+2×API), порты 80/443, исходящий HTTPS-доступ (LLM API, FreshClam, apt), NTP, SSH-доступ, ожидания по их бэкапам; у каждой строки — «почему» одной фразой
- [ ] Отдельно выделено, что должен предоставить заказчик (домен/DNS, offsite-таргет для бэкапов, пароли из `.env.production.example`)
- [ ] `docs/ИМПОРТОЗАМЕЩЕНИЕ.md`: таблица компонент × статус (реестр РФ / зарубежный) × кандидат на замену × риск для проекта; итоговый вердикт по декабрьскому деплою
- [ ] Ни одного выдуманного факта о реестре: всё, что требует сверки с актуальным реестром, помечено явно как «проверить»
- [ ] Оба файла читаются без контекста кодовой базы
