## Что должно заработать

О проблемах платформы владелец узнаёт в Telegram за минуты: упал readiness, недоступна реплика,
устарел бэкап, диск заполняется, offsite не настроен. Активная авария не заваливает сообщениями —
одно уведомление и одно «восстановлено». Деплой сам проверяет здоровье после выката и
автоматически возвращается к предыдущим образам при неудаче. Панель мониторинга больше не видна
интернету и не существует с паролем по умолчанию.

## Критерии приёмки

- [ ] Алертер проверяет: readiness API, доступность реплики и размер/лаг слота, возраст маркера бэкапа (контракт таска 04), заполнение дисков, состояние offsite-шага
- [ ] Дедупликация: активная авария шлёт одно сообщение, при восстановлении — одно «исправлено»; юнит-тесты логики на подставных данных (без реального Telegram)
- [ ] `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` — только переменные окружения; пустые → алертер пишет warning в лог и молчит, не падает; значения секретов нигде не появляются
- [ ] deploy.sh: образы тегируются git SHA; после up — ожидание healthy с таймаутом; при провале автоматический перевкат предыдущих тегов и ненулевой код выхода; ручная процедура отката описана в README
- [ ] У Grafana нет опубликованного порта хоста (только внутренний expose); команда доступа через SSH-туннель — в README; деплой падает, если пароль администратора Grafana пуст или дефолтен (строгий режим распространён на этот секрет)
