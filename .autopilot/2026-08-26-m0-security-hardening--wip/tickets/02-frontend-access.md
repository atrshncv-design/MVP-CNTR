## Что должно заработать

Маршруты личных кабинетов закрыты матрицей ролей, работающей по принципу «не указано — запрещено»,
включая редактор новостей и все появившиеся недавно разделы. Весь клиентский код берёт адрес API
из одного модуля: в продовой сборке физически не остаётся зашитого localhost, а неполная конфигурация
падает при сборке с понятной ошибкой, а не в браузере пользователя.

## Критерии приёмки

- [ ] Матрица ролей явно покрывает каждый существующий маршрут `/dashboard/*`; маршрут без записи → forbidden (запрет по умолчанию)
- [ ] `/dashboard/news/[id]/edit` недоступен роли без права редактирования уже на уровне маршрута (UI-шелл не отдаётся)
- [ ] Регрессионный тест: обходит реальные маршруты из структуры приложения против матрицы — покрытие 100%; добавленный без записи маршрут валит тест
- [ ] В собранном клиентском бандле отсутствуют литералы `127.0.0.1:8000` / `localhost:8000`
- [ ] Production-сборка без необходимой конфигурации URL завершается ошибкой с понятным сообщением (не fallback)
- [ ] Все клиентские вызовы идут через единый модуль; проверка закреплена тестом/grep-правилом
