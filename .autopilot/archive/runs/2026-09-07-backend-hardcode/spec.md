# Спецификация: Бэкенд — каталог сообщений и конфиги

## Задача

API отвечает пользователю зашитым русским текстом при любой локали, а адреса и лимиты разбросаны по коду. Владелец хочет, чтобы ошибки несли стабильный код и текст на языке запроса, а окружение-зависимые значения жили в конфиге — не ломая при этом фронт, который понимает `detail` только как строку.

## Решение

После прогона каждая пользовательская ошибка API несёт стабильный код в заголовке ответа и текст на языке запроса в теле, адреса и порты читаются из окружения с задокументированными именами, а повторный сканер и живые пробы подтверждают отсутствие новых зашитых строк при зелёной сюите.

## Пользовательские истории

| # | Метка | История | Приёмка |
|---|-------|---------|---------|
| 1 | R01 | Как проверяющий, я поднимаю бэкенд одной командой из документации, чтобы сверить работу | health и ready зелёные, команда записана |
| 2 | R02 | Как проверяющий, я вижу замер хардкода до и после, чтобы верить результату, а не глазам | counts сканера и пробы трёх эталонных ошибок приложены |
| 3 | R03 | Как клиент EN-локали, я получаю ошибку по-английски, чтобы понимать, что случилось | неверный логин с `Accept-Language: en` — английский текст |
| 4 | R03.1 | …и ошибка несёт стабильный код, чтобы фронт и внешние потребители ветвили логику не по тексту | заголовок ответа с кодом; тело `detail` — строка как раньше |
| 5 | R03.2 | …а без языкового заголовка всё работает как раньше | без `Accept-Language` — русский текст, тот же статус |
| 6 | R03.3 | …и тексты с подстановками (имена, лимиты) не склеены из кусков | параметры каталога, порядок слов корректен в обеих локалях |
| 7 | R04 | Как владелец стенда, я меняю адреса и порты без правок кода, чтобы поднимать окружения | в коде нет литералов хостов/портов/base URL вне конфига; имена — в `.env.example` |
| 8 | R05i | Как владелец, я получаю сборку без регрессий | сюита бэкенда зелёная, фронт не тронут, логи/сиды/тесты — по-русски как были |

## Решения по реализации

- Каталог сообщений — один модуль с ключами вида `AUTH_INVALID`, текстами ru/en и параметрами. Почему так: единый источник вместо 122 разбросанных строк.
- Код ошибки — в заголовке ответа, тело `detail` остаётся строкой. Почему так: фронт читает только строку/массив, словарь в теле сломал бы показ ошибок без правок фронта, а фронт вне объёма.
- Язык — из заголовка запроса, умолчание русское. Почему так: сохраняет текущее поведение для всех существующих клиентов.
- Тексты оценки готовности — через тот же каталог. Почему так: отдаются через API, значит пользовательские.
- Логи, сиды, тесты — не трогаем. Почему так: прецедент прогона фронта, это рабочее тело, а не отображаемый текст.
- Конфиг — только окружение-зависимое (хосты, порты, base URL внешних сервисов). Почему так: алгоритмические константы от окружения не зависят, их вынос — шум.
- Проверка — сканер из прогона аудита плюс живые пробы трёх эталонных ошибок в обеих локалях. Почему так: сканер ловит статику, пробы — поведение.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `errors` | коды, тексты ru/en, выбор по языку запроса | `raise_error(код[, параметры]) -> HTTPException с кодом в заголовке` | тексты каталога, разбор заголовка |
| `settings` | окружение-зависимые значения | `настройки с именами из .env.example` | парсинг окружения, дефолты |

Швы для тестов — два: каталог (код + текст в обеих локалях на каждый ключ) и живые пробы API (три эталонные ошибки в обеих локалях). Сюита бэкенда — регресс-шов.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Перевод логов/сидов/тестов | рабочее тело, не отображаемый текст — прецедент прогона фронта |
| Правки фронта под новый формат ошибок | фронт понимает строку; контракт выбран обратно совместимым именно чтобы его не трогать |
| Третья локаль | в брифе только полнота ru/en |

## Открытые места

Плейсхолдеров нет. EN-тексты пишет сборка (прецедент прогона фронта), спорные — списком в финальном отчёте.
