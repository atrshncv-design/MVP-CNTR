# 09 — Миграции только с готовым бэкапом

**Требования:** R05i (история 17)
**Blocked by:** —
**Зона:** `infra/backup`
**Волна:** 2
**Status:** ready

## Что должно заработать

Занятый backup-lock блокирует миграции (fail-closed): «бэкап уже идёт»
не трактуется как «бэкап готов»; ручной бэкап по ранбуку всегда делает
снимок, а не пропускается из-за маркера деплоя.

## Из брифа, дословно

> составь спеку и тикеты для внесения правок
> «Всё + приоритеты»: спека покрывает все подтверждённые находки; таски — на Blocker/Critical/High/CI (Дополнения 2026-09-08)

## Разделы спецификации

История 17, Решение §10, Границы `infra-backup`.

## Критерии приёмки

- [ ] Удержанный lock бэкапа → миграции не стартуют, деплой падает внятно
- [ ] Ручной бэкап после деплоя создаёт новый снимок, а не «успех без работы»
- [ ] Коды возврата различают «готово», «занято», «ошибка»
- [ ] Тест на шве shell-контрактов покрывает contention и ручной запуск
