# Границы и правила прогона `hardcode-audit`

## Границы, решённые в спецификации

Аудит идёт в одном контексте (ярус T0) — отдельных публичных сигнатур между исполнителями нет. Логические единицы внутри одного прогона:

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `scan` | правила обнаружения и классификация находок | `scan(repo) -> findings{место, категория, фрагмент}` | парсинг файлов, эвристики, игнор шума |
| `rank` | ранги P0/P1/P2, i18n-вердикт, план выноса | `rank(findings, parity) -> report{ранги, блокеры, план}` | веса рангов, пороги, формулировки |

## Шов для проверки

- Повторный прогон сканера по зафиксированному состоянию даёт те же находки и те же counts (детерминизм, идемпотентная перезапись отчёта).

## Правила проекта (не выводимые из задачи)

- Стек: интерфейс — Next.js + next-intl со словарями двух локалей ru/en; сервер — Python + FastAPI.
- Прогон — только чтение кода платформы; правки продуктового кода запрещены (решение пользователя «Только отчёт»).
- Повторяемость: сканер без зависимости от окружения, детерминированный порядок строк.
- Шум (комментарии, тесты, сгенерированные файлы) — отдельно от основного перечня, в основной список не входит.
- Недостающая зависимость — вернуть `BLOCKED: <имя>` с причиной, не ставить молча.

- `rank`: `.autopilot/2026-09-04-hardcode-audit/report.md` (копия — `reports/hardcode-audit-2026-09-04.md`) + `evidence/findings.json` (2219 находок) + `evidence/summary.json` (counts для гейта).
- Шов проверен: повторный прогон даёт идентичный `summary.json`.

## Что нельзя трогать

- Продуктовый код фронтенда и бэкенда (только чтение).
- `.autopilot/state.js` чужых прогонов, файлы памяти вне `autopilot`-маркеров.
- Секреты: только имена переменных, никогда значения в код/отчёты/логи.
