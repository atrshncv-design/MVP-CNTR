# 03 — Безопасность фронтенда, секреты и история репозитория

**Требования:** R05, R11
**Blocked by:** 01
**Зона:** `technozrelost-frontend/src`, `technozrelost-frontend/next.config.ts`, `.github/`, скан git-истории (read-only)
**Волна:** 2
**Status:** ready

## Что должно заработать

Фронтенд проверен по OWASP-базовой линии: клиентский бандл не выдаёт секретов, защищённые маршруты реально защищены, опасные HTML-вставки отсутствуют или экранированы, заголовки безопасности настроены. История git просканирована на утечки секретов по всем веткам; CI-воркфлоу проверен на права и работу с секретами. Опасное чинится безопасно, остальное — в реестр находок.

## Разделы спецификации

Истории 4, 8; Решения (OWASP-базовая линия, скан истории).

## Чек-лист аудита

- NextAuth: источник секрета, срок жизни сессии, callbacks/jwt, защита middleware всех приватных маршрутов
- `NEXT_PUBLIC_*` и прочие переменные, попадающие в клиентский бандл — нет ли значений-секретов
- `dangerouslySetInnerHTML` / `eval` / рендер пользовательского HTML
- API-клиент: базовые URL, обработка ошибок без утечки деталей, CORS-ожидания
- Заголовки безопасности (CSP, X-Frame-Options, HSTS) в next.config/nginx
- Скан полной истории всех веток по паттернам ключей (sk-, ghp_, AKIA, xoxb, eyJ, соединительные строки, приватные ключи)
- CI: права workflow, пин версий действий, обращение с секретами

## Критерии приёмки

- [ ] Реестр находок: каждая с файлом:строкой, severity, действием
- [ ] Безопасные фиксы применены и проверены (`npm run lint` + `npm test` + `npm run build` зелёные)
- [ ] Отчёт по скану истории: чисто ИЛИ список находок с рекомендацией отзыва ключа (без rewrite истории)
- [ ] Вердикт по CI-воркфлоу
- [ ] `.env*` файлы не читаются в значениях наружу, не коммитятся, история не переписывается
