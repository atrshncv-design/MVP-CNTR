## 4. Текущее состояние платформы

**Проблема и ценность:** долгий цикл НИОКР, разрозненные реестры, нет единого окна для КЗ/ИП и верификации УГТ. Платформа — инфраструктура ЦНТР: собирает проекты, верифицирует УГТ по ГОСТ, связывает ГК—исполнителя—производителя через matching, формирует документы и аналитику.

**Пользователи (факт кода):** 8 активных ролей (эксперт УГТ удалён в P1): `gk_customer` (ГК-заказчик), `rd_executor`, `scientific_org` (клон R&D, один shell), `serial_manufacturer`, `regulating_organization`, `auditor` (КТ Go/No-Go), `investor`, `cntr_admin`, `cntr_manager`. Новые сущности: `UserProfile` (проф. профиль) и `UserOrganization` (пользовательская орг) — тикет 03.

**Сущности:** User, Role, Project (7 статусов), ProjectMember/Invite, QuestionnaireResult (per-user), AssessmentTemplate/Checkpoint, ControlPoint, PromotionRequest, ProjectDocument/VerificationDocument, AuditTrail, RagDocument (tuno/kaba), Organization (справочник), NioktrCard (16k), Technology (проекция Project УГТ≥7), News/Post/Media, Achievement (66), Notification/Outbox, StageRequirement.

**Путь проекта:** `draft → auto_confirmed → published → active → completed` + `→ rejected` (с причиной + HardGateBadge «Возврат на УГТ N») / `→ archived`. Создание `POST /projects` → анкета → документы → PromotionRequest → КТ Go/No-Go → публикация → архив. История — `AuditTrail` лента всем.

**Где AI:** внешний OpenAI-совместимый LLM (`LLM_API_BASE/KEY/MODEL`), по умолчанию `llm_gateway_enabled=false` (N-05, ПДн не покидает контур, allowlist 5 полей без PII, контур tuno/kaba два ivfflat-индекса). Без ключа — no-op. Эмбеддинги — CPU-hashing 1536. Matching — скрипт 5 полей → топ-5, LLM-rerank код готов (`app/services/matching.py:152`) но выключен флагом. GPU не нужен до локального контура (06–07.27).

**Ядро vs вторичное:** ядро — F01 RBAC, F02 ЛК, F03/F06 карточка/статусы, F07 документы, F09/F11 реестры, F16 новости, F12 верификация. Вторичное — AI (F13–F15), гаммификация (F17), аналитика (F19). Отложенного нет — всё к 12.27 (Q01), но S-C7 прогноз и S-D1 межд. данные — после накопления данных.

## 9. Архитектура и функциональные направления

**Направления:** 1) «Единое окно» (реестры, профили, облако смыслов) — S-A; 2) «Конвейер НИОКР» (методика, УГТ, КТ, договоры) — S-B; 3) «Данные и аналитика» (сбор, доступы, отчёты, ИИ, прогноз) — S-C; 4) «Кооперация» (межд. данные, риски, РИД, matching, отчётность) — S-D; 5) «Сквозные» (новости, меры, размещение, геймификация, KPI) — S-E.

**Стек без изменений:** Next.js 16 + FastAPI async + PostgreSQL 16 pgvector + MinIO+ClamAV + Redis + nginx + Prometheus/Grafana. Primary `:5432` запись, Replica `:5433` чтение реестров (`get_read_db()`), пул 10+20×2=40/100.

**AI-архитектура:** DB (открытые данные) → retriever pg_trgm 20 → LLM rerank tuno (без ПДн) → топ-5 с причинами → MatchRequest → модерация → Notification (интервью 14). RAG — два контура tuno/kaba, `contour TEXT CHECK`, два частичных ivfflat `WHERE`. 2026 — облако обезличенно, 2027 — локальный PII-GPU.
