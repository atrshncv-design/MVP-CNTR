# BACKLOG — Реестр находок независимого аудита (2026-08-26)

> Источник: независимая верификация прогона `.autopilot/2026-08-25-deploy-readiness-audit`
> (четыре аудитора: безопасность бэкенда, безопасность фронтенда, инфраструктура, производительность).
> Вчерашний аудит честен по заявлениям, но неполон (~65–70% покрытия доменов); ниже — консолидированный
> реестр из 62 пунктов: подтверждённые пропуски аудита + незакрытые рекомендации самого аудита.
>
> **Правила работы агентов с этим файлом:**
> 1. Один пункт = один таск = одна ветка/коммит-серия. Не смешивать пункты.
> 2. На каждый фикс — тест, воспроизводящий проблему (или проверяющий фикс), и зелёные gates
>    (`uv run pytest`, `ruff`, `mypy` — backend; `npm run lint && npm test && npm run build` — frontend).
> 3. После закрытия пункта: поменять статус на `done` + хэш коммита + дата. Открывать новые пункты можно,
>    менять приоритеты и удалять — нельзя (решение только за CTO/Functional Validator'ом).
> 4. Порядок работы задаёт `Plan.md`; сюда агент приходит за деталями конкретной находки.
> 5. Если фикс требует миграции БД — номер следующей: 0028+.

Приоритетные уровни:
- **P0** — блокеры B2G-деплоя: безопасность, целостность данных, наблюдаемость отказов. Срок — до 30.09.
- **P1** — устойчивость декабрьского демо и честная масштабируемость на 2 реплики. До 15.11 (заморозка).
- **P2** — качество, гигиена, развитие после приёмки.
