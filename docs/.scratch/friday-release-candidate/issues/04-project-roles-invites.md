# 04 — Проектные роли, приглашения и договорное владение

**What to build:** Сделать полный путь создания проекта любым пользователем, безопасного приглашения участников, выбора проектной роли и разделения технического/договорного владения.

**Blocked by:** 03 — Личные профили и организации

**Status:** done

- [x] Создатель получает project_admin и может передать полномочие
- [x] Одноразовые приглашения имеют срок и допустимые роли
- [x] Массовые приглашения имеют лимит и отзыв
- [x] Проектная роль независима от основной роли профиля
- [x] Договорные поля меняет только менеджер
- [x] Отрицательные RBAC/IDOR тесты зелёные

Реализовано: миграция 0017 (`project_invites` single/bulk с max_uses/expires_at/revoked_at, `project_members.is_project_admin`, договорные поля `projects.legal_*`); API `app/api/v1/invites.py` (создание/список/отзыв приглашений, accept с проверкой ролей/срока/лимита, transfer-admin, legal — только менеджер); создатель автоматически owner+admin при создании проекта. Backend `918f25e` (114/114 pytest, ruff чист); frontend `963091a` — панель «Команда проекта» в карточке (приглашения со ссылками `/join/INV-…`, передача admin, договорные поля для менеджера), join-клиент поддерживает INV-токены (роль-ограничение → понятная ошибка). Браузерный E2E: создание приглашения через UI, join INV-токеном, 403 при недопустимой роли.
