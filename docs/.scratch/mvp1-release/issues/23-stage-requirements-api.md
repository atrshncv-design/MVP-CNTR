# 23 — API словаря этапов и автозаявки на повышение УГТ

**What to build:** Движок доработки проекта уровнями N→N+1: карточка показывает требования текущего этапа из словаря (тикеты 20, 16 решения интервью), участники загружают документы этапа; когда комплект укомплектован (кто бы ни залил последний документ) — **автоматически** создаётся заявка на повышение, система даёт предварительную оценку по ГОСТам (LLM+RAG): «документы приняты / не хватает: …». При успехе заявка уходит менеджеру (`pending_manager`), при неуспехе — виден список недостающего, дозагрузка, повтор без ограничений. Созданный проект переоценить нельзя — только этим путём.

**Blocked by:** 20, 21, 22 — Схема данных, экспресс-оценка, очереди менеджера

**Status:** ready-for-agent

- [ ] `GET /api/v1/projects/{id}/stage-requirements` — требования этапа N→N+1 из словаря + статус комплекта (что загружено/не хватает); RBAC: участники проекта
- [ ] `POST /api/v1/projects/{id}/stage-documents` — загрузка документа этапа (title, файл, привязка к требованию); RBAC: любой активный участник проекта
- [ ] Автотриггер: после загрузки последнего недостающего документа → создаётся `promotion_request` (`docs_uploaded`), запускается предварительная оценка
- [ ] `POST /api/v1/projects/{id}/stage-evaluate` — предварительная оценка комплекта LLM по ГОСТам (RAG): успешно / не успешно + список недостающего; результат сохраняется в заявке (`pre_evaluated`); мок LLM в тестах
- [ ] Успешная оценка → заявка `pending_manager` + in-app уведомление менеджеру; неуспешная → заявка остаётся, пользователь дозагружает и перезапускает
- [ ] Повторная оценка/переоценка проекта существующим уровнем → 403 (только N→N+1)
- [ ] Тесты: полнота комплекта → автозаявка (последний документ залил участник, не владелец), оценка успех/неуспех, дозагрузка → повтор, RBAC
