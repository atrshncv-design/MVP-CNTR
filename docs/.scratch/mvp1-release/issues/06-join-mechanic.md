# 06 — Механика вступления в проект (API)

**What to build:** Вступление по токену: при приоритетном шаринге (владелец/админ/менеджер/участник с `is_priority`) — сразу `active`; иначе — заявка `pending`. Управление заявками (список, одобрить/отклонить, смена роли) для приоритетных участников. Регенерация токена (старый инвалидируется). Выдача/снятие приоритета участнику — менеджером ЦНТР. Аудит всех действий.

**Blocked by:** 05 — Создание проекта и сохранение опросника

**Status:** ready-for-agent

- [ ] Вступление по приоритетной ссылке → участник сразу `active`
- [ ] Ручной ввод токена → заявка `pending`, видна приоритетным участникам
- [ ] Approve → `active` с выбранной ролью; Reject → `removed`
- [ ] Регенерация токена делает старый недействительным
- [ ] Менеджер ЦНТР выдаёт/снимает `is_priority` любому участнику
- [ ] Аудит: кто, когда, по какому токену вступил
