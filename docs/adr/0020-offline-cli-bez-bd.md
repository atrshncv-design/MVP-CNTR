# ADR 0020 — Офлайн CLI-пайплайн без БД (ingest без деплоя)

**Дата:** 2026-09-03
**Статус:** принят
**Tier:** T2 — reestr-kompetencii-udgu

## Контекст
MVP должен уложиться в 5–7 дней (R17) и не сломать существующие реестры (R01: импорт в staging, только verified — в публичный реестр). Волновая стратегия делит данные на Wave1 (кафедры/люди/оборудование/патенты — уже в ИС) и Wave2 (миссия/фронтир/заделы/услуги). ЦНТР хочет «выгрузи всё что есть — обработаем на своей стороне» (R15/R22), но сперва ручную верификацию JSON, а не автозаливку.

## Решение
Пайплайн — офлайн CLI `scripts/udgu_ingest/ingest.py --zip archive.zip --out ./out` без БД/миграций/alembic. Выход: `udgu_import.json` (схема платформы) + `report.md` + `report.json` + `warnings.log`. Шаги: CRC → поиск `00_опись.xlsx` → чтение листов → Pydantic → индексация `raw_refs` → валидация/дедупликация → отчёт заполненности %. Перезапуск идемпотентен (перезапись). Никакой записи в Postgres, никакого веб-сервиса.

## Почему (с отвергнутыми)
- **Прямая заливка в БД / alembic-миграция — отвергнута:** нарушает R01 (staging-изоляция), требует схемы `organizations.competencies`/`equipment`/`patents` на проде до верификации; заливка — следующий заход после утверждения JSON (spec «Вне рамок»).
- **Веб-UI загрузки / FastAPI endpoint — отвергнут:** требует деплоя, auth, RBAC, хранения загруженных ZIP, 152-ФЗ-оценки; для разовой выгрузки — overkill, CLI покрывает (spec «CLI покрывает MVP; UI — когда поток регулярный»).
- **Фоновый воркер/очередь (Celery/RQ) — отвергнут:** нет долгоживущих задач, нет смысла в брокере для 10–1000 строк; потоковое чтение `pandas`/`openpyxl` хватает до 10k/лист.
- **OCR/LLM-парсинг raw/PDF в MVP — отвергнут:** raw индексируется как ссылки с подсчётом, глубокий парсинг — Wave3.

## Последствия
- Плюс: работает у ЦНТР на ноутбуке без Primary/Replica, nginx, MinIO; ошибки — человекочитаемый отчёт, не падение (empty лист валиден, interruption — повторный запуск); не трогает прод-схему.
- Минус: нет realtime-валидации для Кашина до отправки (только Excel-подсветка + пост-отчёт); ручной шаг «отдать ZIP → получить отчёт» остаётся.
- Цена: маппинг на платформу — только документация (`mapping.md`/таблица в ТЗ), без кода миграции — требует отдельного тикета на заливку после верификации.
