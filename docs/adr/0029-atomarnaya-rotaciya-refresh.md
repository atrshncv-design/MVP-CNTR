# ADR 0029: Атомарная ротация refresh одним UPDATE

## Контекст
Два параллельных refresh одним токеном при проверке-then-инвалидации дают оба успех.

## Решение
Ротация выполняется одним атомарным UPDATE с условием «ещё не отозван», повторное предъявление отклоняется и отзывает всё семейство.

## Почему
Отвергается check-then-act в два запроса: проигрывает гонку между инстансами всегда. Отвергаются блокировки на уровне приложения: не держатся между репликами и добавляют дедлоки без гарантий.

## Последствия
Гонка закрывается без распределённых локов. Неприятное: легитимный ретрай сети после успеха тоже считается reuse и разлогинивает пользователя, клиент обязан это обрабатывать.
