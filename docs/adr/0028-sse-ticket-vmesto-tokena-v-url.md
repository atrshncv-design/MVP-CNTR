# ADR 0028: SSE по одноразовому ticket вместо токена в URL

## Контекст
Клиент потока не умеет в заголовки, а долгоживущий токен в query оседает в логах и прокси.

## Решение
Авторизованный клиент сначала получает короткоживущий одноразовый ticket, стрим открывается по ticket в query, токен в URL запрещается, query стрима исключается из access-лога.

## Почему
Отвергается `access_token` в query: светится в логах/истории/прокси и живёт долго, отозвать утечку нельзя. Отвергаются долгоживущие ссылки на поток: окно компрометации не ограничивается TTL и одноразовостью.

## Последствия
Логи остаются чистыми, окно кражи ограничивается секундами и одним использованием. Неприятное: нужен двухшаговый обмен, хранение использованных ticket и обработка просрочки/повтора на клиенте.
