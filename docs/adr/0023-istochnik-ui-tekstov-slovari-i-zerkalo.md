## Контекст

EN-локаль неполна: строки зашиты в экраны мимо словарей, новые страницы копируют приём. Нужен единый источник текстов с паритетом ru/en и проверкой цифрой.

## Решение

Источник UI-текстов — существующие словари next-intl, ключи по неймспейсам фич. Живая пара — в каталоге исходников, её грузит серверная конфигурация локали; вторая пара зеркалится один в один, расхождения запрещены.

## Почему

Отвергнуто: отдельный механизм строк (CMS или таблица в БД) — новая возможность и новая точка отказа ради выноса; разрозненные JSON рядом с компонентами — рассыпает паритет и проверку; удаление дубля словарей сейчас — ломает конфигурацию с fallback и тесты, смотрящие обе пары; автоперевод и третья локаль — вне брифа, где требуется только полнота ru/en.

## Последствия

Плюс: один шов проверки (counts сканера плюс паритет ключей), переключение локали даёт полный EN без правок кода. Минус: словарь — общий ресурс, дубли ключей запрещены и параллельные правки требуют координации; инвариант «пары идентичны» держим до отдельной чистки.
