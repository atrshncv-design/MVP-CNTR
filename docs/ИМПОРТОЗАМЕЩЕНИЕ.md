# Оценка стека «Технозрелость» на импортозамещение

Документ отвечает на вопрос: что в технологическом стеке платформы мешает требованию
отечественного ПО, чем заменяется и что это значит для декабрьского деплоя.
Оценка дана по составу production-контура (compose-стек) и манифестам зависимостей.

**Методика классификации:** «реестр РФ» — ПО из Единого реестра российского ПО;
«зарубежное свободное» — открытый код с зарубежным правообладателем (лицензии MIT/BSD/Apache/GPL);
«зарубежное проприетарное» — закрытое коммерческое ПО. В текущем стеке проприетарного
зарубежного ПО нет вообще.

> Все утверждения о составе реестра и лицензиях конкретных продуктов помечены
> **[проверить по актуальному реестру]**: реестр пополняется, статусы меняются,
> перед закупкой/решением сверяйтесь с действующей версией на reestr.digital.gov.ru.

## Вердикт для декабрьского деплоя

**Полное импортозамещение к декабрю невозможно** — и важно понимать, где именно граница:

1. **Блокируют любое требование**: языковые платформы и их библиотеки (Python/FastAPI,
   Node.js/React/Next.js, прикладные пакеты). Это свободный открытый код без российских
   аналогов; его «замена» — это разработка платформы заново, счёт идёт на кварталы.
2. **Ключевой процессный вопрос — формулировка требования у заказчика.** Требования
   «реестрового ПО» обычно распространяются на закупаемое проприетарное ПО; свободное ПО
   с открытыми лицензиями в большинстве применяемых методик допускается. Запросите точную
   формулировку требования и методику проверки до любых переделок — возможно, менять
   придётся немногое.

**Что реально заменить к декабрю с приемлемым риском** (параллельно пилоту, без остановки
разработки): ОС → Astra/РЕД ОС после стендовой проверки; PostgreSQL → Postgres Pro
(проверив pgvector); nginx → Angie; MinIO → S3-совместимое хранилище заказчика;
ClamAV → Dr.Web/Kaspersky (нужна доработка интеграции по ICAP).

**Рекомендуемая стратегия:**

- **Пилот в декабре — на текущем стеке.** Он целиком состоит из свободного ПО:
  ничего не закупается, лицензионных рисков нет, деплой не блокируется.
- **Параллельно — дорожная карта замещения** по таблице выше: сначала низкорисковые
  пункты (СУБД, веб-сервер, хранилище), затем антивирус и мониторинг, каждый шаг —
  со стендовой проверкой и откатом назад.
- **Немедленный полный перевод** означает сдвиг срока на несколько кварталов и бюджет
  новой разработки (frontend/backend) — рекомендовать его можно только при жёсткой
  обязательной формулировке требования, распространяющейся на свободное ПО.
