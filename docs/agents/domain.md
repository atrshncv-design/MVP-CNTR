# Domain Docs

Engineering skills consume domain documentation using a single-context layout.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read ADRs under `docs/adr/` that affect the area being changed.
- If these files do not exist, proceed without creating placeholders.

## Vocabulary

Use the domain terms defined in `CONTEXT.md` in ticket titles, tests, schemas and implementation notes. Do not introduce synonyms that conflict with the glossary.

## Architecture decisions

Surface any conflict with an existing ADR explicitly instead of silently overriding it.
