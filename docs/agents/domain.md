# Domain Docs

Engineering skills use a single-context domain documentation layout.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant decisions under `docs/adr/` when they exist.
- Proceed silently when these files do not yet exist.

## Vocabulary

Use the domain terms defined by `CONTEXT.md` in specs, tickets, tests and implementation. When a required term is absent, note the modeling gap instead of silently inventing competing vocabulary.

## Architecture decisions

If proposed work conflicts with an ADR, surface the conflict explicitly and do not silently override the decision.
