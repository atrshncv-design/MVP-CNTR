## 6. Сценарий демонстрации (= чек-лист приёмки)

Каждый шаг = ожидаемый наблюдаемый результат. Поддерживать этот список актуальным.

1. **Публичная часть:** лендинг открывается, реестр НИОКТР ищется по названию/организации/региону за < 2 с, карточка организации с её разработками.
2. **Регистрация и вход:** регистрация исполнителя (R&D/ВУЗ) → профиль draft → отправка на проверку → менеджер подтверждает.
3. **Жизненный цикл проекта:** экспресс-оценка УГТ → создание проекта → приглашение участника (по исправленной механике N-01) → загрузка документов этапа (ClamAV fail-closed виден в статусе) → автозаявка на повышение при полном комплекте → менеджер одобряет → УГТ N→N+1 → публикация в реестре технологий.
4. **AI:** вопрос ассистенту по ГОСТ Р 58048-2017 → ответ с источниками; генерация скелета документа этапа. (Fallback-режим при недоступности LLM показывается честно.)
5. **Надёжность (по запросу заказчика):** панель Grafana/метрики, факт наличия бэкапов, алерт в Telegram при остановке сервиса.

## 7. Definition of Done — для ЛЮБОГО таска любого агента

1. Код написан; комментарии/докстринги по-русски и объясняют «почему».
2. Тест(ы) на новую логику И на каждый исправленный дефект (воспроизводящий баг).
3. Gates зелёные: backend `uv sync --extra dev && uv run pytest -q && uv run ruff check . && uv run mypy app` ; frontend `npm run lint && npm test && npm run build` (build — при остановленном dev-сервере!).
4. Если менялась схема БД — миграция alembic (следующая номером после head), downgrade работает.
5. Индекс под каждый новый частый фильтр (Hash — точный поиск, B-Tree — диапазоны).
6. Пункт BACKLOG.md переведён в done с хэшем коммита; строка в Status.md добавлена.
7. Коммит отправлен в origin (push-контракт AGENTS.md). Работа ведётся в ветке от актуального main.
8. Никогда: секреты в коде/логах/коммитах; значения `.env*` в отчётах; правки чужих чекаутов; самостоятельные решения о приоритетах.

## 8. Процесс контроля качества (solo + агенты)

- **Ревью:** каждый значимый таск проходит независимое код-ревью субагентом ДО передачи владельцу
  (чек-лист ревьюера: соответствие таску, тесты, безопасность, следование соглашениям кода из памятки).
- **CI как второй ревьюер:** ни один коммит не считается завершённым без зелёного CI (после G1).
- **Еженедельный техотчёт** (пятница, шаблон):
  1. Что выпущено (коммиты/тикеты)
  2. Что задерживается и почему
  3. Главные технические риски недели
  4. Инциденты (кол-во, время восстановления)
  5. Состояние бэкапов и алертов (последняя проверка)
  6. Критический техдолг (движение по BACKLOG.md: закрыто/осталось)
  7. Решения, требующие вмешательства владельца
- **Столл-правило:** 25 итераций на задачу; зацикливание или красные тесты после 2 кругов правок — стоп, эскалация владельцу (контракт автономности).
