# 14 — Мэтчинг LLM через центр

Источник Q17

Сторона-заявитель публикует: проект/технология/задача/статья → LLM мэтчинг рекомендует кому полезна (из БД реестров МТК/ВУЗы/компетенции). Обратно: задача → список исполнителей.

Архитектура: DB (открытые данные) → retriever (pg_trgm + vector) top_k 20 → LLM rerank (обезличенно, без ПДн, contour=tuno) → топ-5 с объяснением «почему». Коммуникация: заявитель жмёт «предложить» → создаётся `MatchRequest` → центр модерирует → `Notification` исполнителю. Нет прямых контактов, только через центр (закрытые данные не утекают).

MVP до 01.12: скриптовый фильтр по sector/угт/регион (P-05 индексы) + LLM rerank top-5, 1 endpoint POST /match, очередь как llm-eval.

## V2 — кросс-отраслевой (Q18)
LLM strong model (GPT-4o/Qwen 14B) берёт `project.annotation` + `technology` → анализирует «призма технологии» → ищет в tuno не только прямой sector, а смежные (wood → furniture/chem/construction) через embedding similarity (vector) + LLM reasoning. Возвращает топ-5 с аргументацией «почему полезно» + fallback «нет прямых — вот 3 неочевидных». Гарантия непустого ответа.
