# БД кэш vs диск — почему не 0 ГБ

## Твой вопрос верный
Карточки показываются из БД по API `GET /nioktr` `nioktr.py:56` -> `SELECT` -> `asyncpg` -> `JSON` -> `frontend`. Данные на диске NVMe `pg-prod-primary-data`, не в RAM.

## Почему БД все равно жрет RAM
PostgreSQL RAM — не хранилище, а **кэш горячего**:
- `shared_buffers` 2 ГБ (из 16 ГБ хоста) — кэширует последние 10k карточек + индексы GIN `P-05` + vector
- Без кэша: каждый `ILIKE '%древесина%'` -> `seq scan` 16k -> диск 5мс -> p95 800мс
- С кэшем 2 ГБ: hot 10k в RAM -> 0.2мс -> p95 200мс (твой SLO 500мс)

## Почему не 0 и не 64
- 0 ГБ — каждый запрос в диск, 714 RPS *5мс = 3.5с очередь -> ляжет
- 2 ГБ на 16k карт (16k*5КБ=80МБ + индексы 200МБ) хватает, 80МБ hot в 2 ГБ
- 32 ГБ нужно только на 1М карт (1М*5КБ=5ГБ + vector 6ГБ) hot 5ГБ в 8 ГБ shared

Все большие сервисы (WB, Госуслуги) так же: данные на диске, RAM — только hot 5-10% + индексы. Ты прав — не нужно 64 ГБ на 16k, 2 ГБ хватит. Я перегнул на 1М.

## Для тебя 5К
PG 16 ГБ (shared 4ГБ) + Replica 8 ГБ (2ГБ) = 6 ГБ кэша, остальное App/MinIO. 84 ГБ кластера — не БД одна, а весь `compose.prod.yml`.
