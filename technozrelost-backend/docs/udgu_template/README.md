# Шаблон выгрузки УдГУ для реестра потенциала УР

Назначение: единый машиночитаемый шаблон, пригодный для импорта в платформу
«Технозрелость» (реестры компетенций региона). Даёт ЦНТР и УдГУ общий язык:
что именно перечислять и в каком виде отдавать, чтобы максимально показать
компетенции университета без месяцев ручной работы.

## Состав

- `00_опись.xlsx` — сводный Excel-шаблон (7 листов + `00_инструкция` + `99_raw_опись`).
  Каждый лист — normalized view тематической папки с фиксированными заголовками,
  валидацией и примером строки.
- `schema/udgu_template.schema.json` — JSON-схема импорта (`UdguImport`),
  источник правды для CLI-пайплайна.
- `README_УдГУ_выгрузка.md` — ТЗ-инструкция для Кашина (что/в каком виде).
- `example/УдГУ_*.zip` — пример архива по папкам по темам.

## Разделы (7 + расширяемые)

1. `01_кафедры_и_лаборатории` — кафедры/лаборатории (→ Organization)
2. `02_приоритеты_и_заделы` — научные заделы, TRL 1-9 (→ competency)
3. `03_миссия_фронтир` — миссия, фронтир 3-5 направлений, стратегия
4. `04_оборудование` — оборудование, доступность для МСП (→ Equipment)
5. `05_РИД_патенты_публикации` — патенты/публикации/ПО (→ Patent)
6. `06_услуги_МСП` — услуги для МСП (→ ServiceOffering)
7. `07_люди_эксперты` — люди/эксперты (→ UserProfile)
8. `08_...`, `09_...` — расширяемые секции (extra_sections), без изменения кода
9. `raw/` — индекс сырых файлов без требования форматирования (→ raw_refs)

Волновая стратегия: Wave1 (01,04,05,07) за 5-7 дней валиден; Wave2 — остальное
без дедлайна. Пустая папка + строка «нет данных» — валидно.

## Правила

- ФИЗформа — ZIP `УдГУ_потенциалУР_YYYY-MM-DD.zip` по папкам по темам.
- Excel — ядро, документы/PDF/фото — приложения в папках, ссылка из ячейки.
- `competencies: list[str]` как в платформе; `trl: 1-9` валидируется строго.
- Расширение: добавить папку `08_мой_тип/` + лист по шаблону, пайплайн
  подхватит через `extra_sections` без кода.

## Связь с платформой

Маппинг полей таблицы — в `mapping.md`. Импорт идёт в staging,
только verified попадает в публичный реестр (R01).

## Что будет после выгрузки

> **Верификация ЦНТР → заливка**.

1. Кашин передаёт `УдГУ_потенциалУР_YYYY-MM-DD.zip` в ЦНТР.
2. ЦНТР: `scripts/udgu_ingest/ingest.py --zip УдГУ_*.zip --out ./out` → `udgu_import.json` + `report.md` + `report.json` + `warnings.log`.
3. Верификация ЦНТР: проверка `report.md` (заполненность `%`, пустые разделы, сырые файлы, ошибки по строкам, `Wave2 — что доделать`, `raw_refs` сводка) и `udgu_import.json` по схеме.
4. Только verified данные заливаются в реестры (`organizations`, `competencies`, `equipment`, `patents`, `services`, `people`). Staging → prod (R01).
5. Итерация Wave2: дополнить пустые разделы, 08_... — без изменения кода через `extra_sections["08_доп_тип"]`. Повторный прогон идемпотентен (выход перезаписывается).

См. `README_УдГУ_выгрузка.md` §11 и `mapping.md` для таблицы маппинга и примера до/после.
