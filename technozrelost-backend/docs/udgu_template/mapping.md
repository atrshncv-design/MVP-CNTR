# Маппинг полей шаблона УдГУ на модели платформы «Технозрелость»

> Почему этот файл: отвечает на R20 — как поля `00_опись.xlsx` ложатся в реестры потенциала УР без кода миграции. Импорт готовит `udgu_import.json` в staging, только verified попадает в прод.

## Таблица маппинга

Как поля шаблона (листы `00_опись.xlsx` + папки) отображаются в `scripts/udgu_ingest/models.py` (`UdguImport`) и в реестры платформы `app/db/models.py`.

|---|---|---|---|---|---|
| 01 кафедры и лаборатории | `01_кафедры_и_лаборатории/` | `название*`, `факультет_институт`, `руководитель`, `описание`, `компетенции` (`;`), `файл_приложение` | `departments[].name`, `faculty`, `head`, `description`, `competencies: list[str]`, `raw_refs` | `organizations` (тип=кафедра/лаборатория) + `competencies` | Организация с компетенциями; `competencies` как в платформе `app/db/models.py:competencies` |

| 06 услуги для МСП | `06_услуги_МСП/` | `название*`, `описание`, `формат` (консалт/испытания/НИОКР), `компетенции`, `сроки`, `порядок_цены`, `кейсы` (`;`), `контакт`, `файл_приложение` | `services[].name`, `description`, `format`, `competencies`, `terms`, `price_order`, `cases`, `contact`, `raw_refs` | `services` (ServiceOffering) | Услуга с условиями для МСП |
| 07 люди и эксперты | `07_люди_эксперты/` | `ФИО*`, `должность`, `кафедра_лаборатория`, `компетенции` (`;`), `контакты`, `файл_приложение` | `people[].full_name`, `position`, `department`, `competencies`, `contacts`, `raw_refs` | `people` (UserProfile/эксперты) | Эксперт с компетенциями |
| 99 raw опись | `raw/` | `файл*`, `тип_сущности`, `id_сущности`, `описание` | `raw_refs[].file`, `entity_type`, `entity_id`, `description` | индекс файлов (не реестр) | Сырые файлы без форматирования; папка `raw/` + любые файлы в тематических папках → `raw_refs`, R16: количество в отчёте и `raw_refs` |
| 08_... расширяемые | `08_мой_тип/` | любые заголовки по шаблону | `extra_sections["08_мой_тип"]: list[dict]` | расширяемо (без кода) | R24: добавить папку + лист `08_...`, пайплайн без изменения кода кладёт в `extra_sections["08_доп_тип"]` |

Типы общие: `competencies: list[str]` как в платформе (`app/db/models.py:competencies`), `trl: int ge=1 le=9`, `year: int ge=1900 le=2026` (warning «год ожидается 1900-2026»), `available_for_sme: bool` (Да/Нет), лимит 10k строк/лист → warning «превышен лимит 10k, обработано 10000».

## Связь с верификацией и заливкой

После выгрузки пайплайн `scripts/udgu_ingest/ingest.py --zip УдГУ_*.zip --out ./out` даёт `udgu_import.json` + `report.md` + `report.json` + `warnings.log`. Верификация ЦНТР → заливка: ЦНТР проверяет `report.md` (заполненность %, пустые разделы, сырые файлы, ошибки по строкам, Wave2) и `udgu_import.json`, только verified записи идут в публичный реестр (R01). Повторный прогон идемпотентен — выход перезаписывается.
