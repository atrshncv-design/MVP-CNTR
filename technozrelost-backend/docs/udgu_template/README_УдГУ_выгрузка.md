# ТЗ-инструкция: выгрузка УдГУ для реестра потенциала УР

**Получатель:** Кашин (УдГУ) и команда университета  
**Заказчик:** ЦНТР, платформа «Технозрелость», реестры потенциала Удмуртской Республики (ГОСТ Р 58048-2017)  
**Дата шаблона:** 2026-09-03  
**Версия:** 1.0

## 1. Цель

Собрать выгрузку компетенций ФГБОУ ВО «Удмуртский государственный университет» для загрузки в **реестр потенциала УР** платформы «Технозрелость». Данные лягут в региональные реестры: организации/лаборатории, компетенции, оборудование, РИД (патенты/публикации/ПО), услуги для МСП, эксперты. Цель — **максимально показать компетенции университета** без месяцев ручной чистки: вы выгружаете как есть, ЦНТР нормализует на своей стороне.

Импорт идёт в staging-схему, только verified записи попадают в публичный реестр (R01).

## 2. Физическая форма — ZIP-архив по папкам по темам

Единственная принимаемая форма — **ZIP-архив**:

```
УдГУ_потенциалУР_YYYY-MM-DD.zip
├── README_УдГУ_выгрузка.md      # эта инструкция (копия)
├── 00_опись.xlsx                # сводный Excel — ядро (обязательно)
├── 00_опись.pdf                 # человекочитаемая копия описи
├── 01_кафедры_и_лаборатории/    # файлы темы (фото, PDF, паспорта)
├── 02_приоритеты_и_заделы/
├── 03_миссия_фронтир/
├── 04_оборудование/
├── 05_РИД_патенты_публикации/
├── 06_услуги_МСП/
├── 07_люди_эксперты/
├── 08_extra_example/            # пример расширяемой секции (опционально)
└── raw/                         # сырые дампы без обработки (опционально)
```

**Конвенция имени архива (рекомендация, не строго):** `УдГУ_потенциалУР_YYYY-MM-DD.zip`, пример `УдГУ_потенциалУР_2026-09-03.zip`. Дата — день формирования. Пайплайн принимает любое имя `*.zip`, но конвенция помогает версионированию.

**Правила:**
- Кодировка имён — UTF-8.
- В корне обязателен `00_опись.xlsx`; `00_опись.pdf` и `README` — желательны.
- Сырые файлы можно класть как в тематическую папку, так и в `raw/` — пайплайн проиндексирует всё.
- Пустая тематическая папка — валидно (см. §6).
- Ошибочное имя папки/листа — не падает: пайплайн сопоставляет по нормализованному имени (lowercase, без пробелов/дефисов) и пишет в отчёт «нераспознанная папка X — проигнорирована».

## 4. Правило «таблички — ядро, документы — приложения»

- **Ядро:** `00_опись.xlsx` — машиночитаемая нормализованная выгрузка. Заполните заголовки, 1+ строк на лист (или «нет данных»). Пайплайн читает только его строго (валидация, типы).
- **Приложения:** любые документы/PDF/фото/паспорта/выгрузки из ИС УдГУ — в тематических папках или `raw/`. Ссылка из ячейки `файл_приложение` на файл — желательна, но не обязательна: файл без ссылки всё равно индексируется, ссылка без файла — warning.
- **Сырые «грязные» данные:** принимаются без чистки. Кладёте как есть в `raw/` или в папку темы. Пайплайн не парсит их, только индексирует и считает в `raw_refs`.
- **Фото/паспорта оборудования:** файл в `04_оборудование/`, ссылка в `файл_приложение`.

## 5. Инструкция расширения 08_...

Примеры в ТЗ не исчерпывающие — у УдГУ больше типов (R24). Чтобы добавить новый тип:

1. Создайте папку `08_мой_тип/` (префикс `08_`, `09_...` — любой, латиница/кириллица, без пробелов в начале).
2. Создайте лист `08_мой_тип` в `00_опись.xlsx` по шаблону любого раздела: заголовок + пример строки.
3. Заполните строки; в `файл_приложение` — ссылки на файлы из `08_мой_тип/`.

Пайплайн подхватит новую секцию без изменения кода: данные попадут в `extra_sections["08_мой_тип"]` (требование R24). В `example/` приложен демо `08_extra_example/`.

## 6. Пустые секции — валидно

- **Лист:** если по теме нет данных — оставьте заголовок и одну строку со значением `нет данных` в первом столбце (остальные пустые). Пайплайн считает раздел пустым, не падает.
- **Папка:** пустая папка — валидно (нет файлов по теме). Не удаляйте папку — её наличие показывает, что тема просмотрена.
- **raw/:** может отсутствовать целиком.

Отражено в валидации Excel (подсказки) и в `00_инструкция`.

## 7. Чек-лист волн — что сдавать первым

### Wave1 — MVP 5-7 дней (достаточно для первого показа)

Сдаётся как валидный архив, платформа уже строит первый срез потенциала.

- [ ] `01_кафедры_и_лаборатории` (01_кафедры_лаб) — что уже в ИС УдГУ
- [ ] `04_оборудование` — по паспортам
- [ ] `05_РИД_патенты_публикации` — патенты/публикации
- [ ] `07_люди_эксперты` — ключевые эксперты
- [ ] `00_опись.xlsx` с этими 4 листами заполнен, остальные листы — «нет данных» + пустые папки — валидно
- [ ] `raw/` — опционально любые дампы

**Критерий готово к импорту Wave1:** архив распаковывается, `00_опись.xlsx` открывается, 4 листа Wave1 имеют ≥1 содержательной строки, пайплайн `ingest.py --zip ... --out ...` даёт `udgu_import.json` без ошибок.

### Wave2 — без дедлайна (полнота)

- [ ] `02_приоритеты_и_заделы` — научные заделы, TRL, коллаборации
- [ ] `03_миссия_фронтир` — миссия, фронтир 3-5 направлений, стратегия

Wave2 дополняет Wave1, не ломая формат: добавьте листы/папки и перезапустите пайплайн.

## 8. Конвенция имени архива

Рекомендуемый формат: `УдГУ_потенциалУР_YYYY-MM-DD.zip`

Примеры:
- `УдГУ_потенциалУР_2026-09-03.zip` — выгрузка на 3 сентября 2026
- `УдГУ_потенциалУР_2026-10-01.zip` — обновление

Правила: префикс `УдГУ_потенциалУР_`, дата ISO, расширение `.zip`. Допустимо любое имя `*.zip` — пайплайн не строго проверяет, но конвенция нужна для версионирования в ЦНТР.

## 10. Как заполнять Excel

1. Откройте `00_опись.xlsx` в Excel/LibreOffice.
2. Лист `00_инструкция` — прочитайте подсказки; комментарии к заголовкам — подсказки по полям.
3. На каждом листе — заголовок + 1 пример строки (светло-серая заливка примера). Замените пример своими данными или оставьте заголовок + «нет данных», если данных нет.
4. `компетенции`, `авторы`, `коллаборации` — через `;`. TRL — число 1-9 (валидация). Год — 1900-2100. Да/Нет — выбор из списка.
5. `файл_приложение` — впишите относительный путь к файлу в папке, напр. `04_оборудование/фото.jpg`. Сам файл положите в эту папку.
6. Не удаляйте листы — пустой лист с «нет данных» валиден. Не переименовывайте префиксы `01_...` — пайплайн сопоставляет по ним.
7. Сохраните, положите в корень ZIP вместе с папками.

Валидация в Excel подсвечивает ошибки (выпадающие списки, формат дат), но окончательная проверка — `ingest.py` с отчётом по строкам.

## 11. Что будет после выгрузки

1. Вы передаёте ZIP в ЦНТР.
2. ЦНТР прогоняет `scripts/udgu_ingest/ingest.py --zip УдГУ_*.zip --out ./out` → получает `udgu_import.json` + `report.md` + `report.json` + `warnings.log`.
3. Верификация: ЦНТР проверяет `report.md` (заполненность %, пустые разделы, сырые файлы, ошибки по строкам) и `udgu_import.json`.
4. Только verified данные заливаются в реестры платформы (staging → prod).
5. Итерация: по `Wave2 — что доделать` вы дополняете выгрузку и передаёте новый ZIP.

## 12. Частые вопросы

- **Нет данных по теме?** — строка «нет данных» + пустая папка — валидно.
- **Ошибся в имени папки?** — пайплайн сообщит «нераспознанная папка X — проигнорирована», данные не потеряются, но лучше поправить на `01_...` и т.д.
- **Много сырых файлов?** — кладите всё в `raw/` и/или тематические папки, пайплайн проиндексирует, лимит 10k строк на лист с предупреждением.
- **Новый тип данных?** — инструкция §5, префикс `08_...`.
