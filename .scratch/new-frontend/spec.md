# Spec: новый frontend-контур платформы ЦНТР Удмуртской Республики

Feature slug: `new-frontend`
Worktree: `.worktrees/new-front` (ветка `new-front`), приложение в `platform/`
Документация-источник: `platform/docs/new-front/` (Design.md, CONTEXT.md, ROUTES.md, ROLES.md, DATA-CONTRACTS.md, STATES.md, TICKETS.md — копия локальной папки `new-front/`)
Статус: ready-for-agent (P0)

## 1. Цель

Создать самостоятельный параллельный frontend-контур цифровой платформы Центра научно-технологического развития Удмуртской Республики, визуально и сценарно проверяемый ДО интеграции с текущим бэкендом. Текущий фронтенд (`technozrelost-frontend`) не трогается. Бэкенд не переписывается. Интеграция — только после визуальной/сценарной приёмки, через замену адаптера.

## 2. Архитектура

- **Расположение:** отдельный git-worktree `.worktrees/new-front`, ветка `new-front`, приложение `platform/`. Текущие файлы worktree (CLAUDE.md, Status.md, КОД MVP "0" и пр.) не изменяются.
- **Стек (текущий стек проекта, без изменений):** Next.js 16 App Router, React 19, TypeScript 5, Tailwind CSS v4 (CSS-first токены), lucide-react (единая иконографика), framer-motion (функциональная анимация). Изменение стека не требуется — обоснований нет.
- **Слои (контракт DATA-CONTRACTS §1):**
  `UI-компоненты → route loaders/actions → типизированный domain data layer → PlatformDataAdapter (mock | real)`.
  Компоненты НЕ вызывают URL бэкенда напрямую. Единственная точка интеграции — адаптер.
- **Типы и адаптер:** интерфейс `PlatformDataAdapter` и формы данных из DATA-CONTRACTS §3–4 (`TechnologySummary`, `TechnologyDossier`, `CustomerRequest`, `ResearchRecord`, `OperationalTask`, `ListQuery`, `Page<T>` и т.д.). Mock-адаптер работает от локальных фикстур; real-адаптер (fetch к `/api/v1`) реализуется с тем же интерфейсом, подключается переменной окружения `DATA_ADAPTER=mock|api` и в P0 по умолчанию `mock`.
- **Шеллы:** публичный `/(public)` (задача-first навигация), авторизованный `/(app)` (sidebar + контекстный top bar), операционный `/(operations)` (Центр, плотные очереди), auth-маршруты (`/login`, `/register/*`).
- **Темы:** светлая / тёмная / удмуртская через семантические CSS-переменные (Design.md §9). Один компонент — три визуальных мира. По умолчанию `prefers-color-scheme`, ручной выбор персистится (localStorage `nfr-theme`), стартовый inline-скрипт без FOUC.
- **Авторизация P0:** mock-сессия (демо-роль переключается в UI), демо-аккаунты зеркалят бэкенд: `demo.gk@example.com` (gk_customer), `demo.rd@example.com` (rd_executor), `demo.manager@example.com` (cntr_manager), `demo.admin@example.com` (cntr_admin), `demo.investor@example.com` (investor). Настоящий auth (NextAuth) — на этапе интеграции.

## 3. Маршруты (ROUTES.md — полный инвентарь)

- **Публичные:** `/` (entry + два действия), `/find`, `/technologies`, `/technology/:id`, `/requests`, `/request/:id`, `/partners`, `/partner/:id`, `/support`, `/competitions`, `/pilots`, `/research`, `/research/:id`, `/investments`, `/events`, `/map`, `/about`, `/methodology`, `/levels`, `/roadmap`, `/customers`, `/performers`.
- **Auth:** `/login`, `/register`, `/register/organization`, `/register/role`, `/register/confirm`, `/register/pending`, `/forgot-password`, `/reset-password`.
- **Общие авторизованные (`/app`):** `/app`, `/app/notifications`, `/app/documents`, `/app/profile`, `/app/organization`, `/app/settings`, `/app/help`.
- **Заказчик:** `/app/customer`, `/app/customer/requests`, `.../requests/new`, `.../requests/:id`, `/app/customer/search`, `.../shortlists`, `.../pilots`, `.../pilots/:id`.
- **Исполнитель:** `/app/partner`, `.../technologies`, `.../technologies/new`, `.../technologies/:id`, `.../technologies/:id/evidence`, `.../technologies/:id/path`, `/app/partner/applications`, `.../requests`, `.../pilots`.
- **Научная организация:** `/app/science`, `.../research`, `.../research/new`, `.../partners`.
- **Инвестор:** `/app/investor`, `.../technologies`, `.../expertise`, `.../watchlist`.
- **Эксперт/аудитор:** `/app/expert`, `.../queue`, `.../reviews/:id`, `.../history`.
- **Операционный центр:** `/operations`, `.../queue`, `.../submissions`, `.../verification`, `.../technology`, `.../technology/:id`, `.../requests`, `.../organizations`, `.../research`, `.../pilots`, `.../decisions`, `.../analytics`, `.../settings`.

Каждый маршрут: роль → объект → решение/действие → следующий шаг. Маршрут без данных — честное пустое/ошибочное состояние, не статичный заголовок.

## 4. Роли (ROLES.md)

P0 полное покрытие: заказчик (customer request), промышленный партнёр/исполнитель (technology dossier), сотрудник Центра (операционная задача). Остальные роли (научная организация, серийный производитель, инвестор, эксперт/аудитор, регулирующая организация, менеджер, администратор, публичный посетитель) — маршрутные шеллы с правдоподобными loading/empty/error/permission состояниями. Визуальная семантика: публичное — редакционное, кабинеты — инструментальные, операционный центр — плотный.

## 5. Данные и адаптер

**Политика реальности (DATA-CONTRACTS §2):** не выдумывать компании, технологии, проекты, показатели, даты, пилоты, инвестрезультаты.

- **Реальные данные P0:** НИОКТР — 400 реальных карточек из `data/nioktr_sample.json` бэкенда (источник: МИНОБРНАУКИ России; поля: registration_number, name, annotation, keywords, nioktr_types, state_program, created_date, is_ai_area, is_ai_usage, executor, customer; provenance сохраняется). Организации — производный справочник из полей executor/customer карточек НИОКТР.
- **Честные пустые состояния:** технологии (dossier), запросы заказчиков, партнёры, пилоты, поддержка, конкурсы, инвестиции, события — «Пока нет опубликованных записей» / «Данные проходят проверку» / «Раздел готов к наполнению» / «Источник данных временно недоступен».
- **Контролируемые UI-фикстуры (DATA-CONTRACTS §5):** для проверки сценариев в авторизованных кабинетах (статусы draft/under_review/clarification/approved/rejected/published, УГТ-путь, заявки, пилоты) допускаются фикстуры с `isFixture: true`, помеченные в UI бейджем «Тестовый пример для проверки интерфейса», НИКОГДА не попадающие в публичные реестры. Публичные экраны показывают только реальные записи или пустые состояния.
- **Путь УГТ:** УГТ 1–9 (низкий 1–3, средний 4–6, высокий 7–9), 4 измерения, checkpoint'ы, evidence, N→N+1, трёхлетний отчётный путь. УГТ — не общая оценка качества.

## 6. Темы (Design.md §9–10)

Токены (семантические, без хардкода в компонентах): canvas, surface, elevated, border subtle/strong, text primary/secondary/muted/inverse, accent primary/soft, link, focus, success/warning/danger/info, UGT low/medium/high, overlay/scrim. Статусы семантически одинаковы во всех темах. Удмуртская тема — не замена цветов: чёрно-красно-белая база, восьмиконечная звезда и модульная геометрия в разделителях/маркерах/прогрессе, без флага на каждом экране. Анти-slop (Design.md §6.2): без одинаковых карточек-прямоугольников, без синего везде, без uppercase-monospace-подписей везде, без grid-фонов и glow как декорации, без пилюль для обычных кнопок. Контраст WCAG AA с самого начала (урок текущего фронта: `#94a3b8`/`#d97706`/`#16a34a` в светлой теме не проходят AA).

## 7. Порядок P0/P1/P2

P0: T-001 токены/темы → T-002 публичный shell, T-003 авторизованные shell'ы, T-004 data layer + реальные фикстуры, T-005 state system → T-006 discovery, T-007 dossier, T-008 кабинет заказчика, T-009 кабинет партнёра, T-010 операционный центр, T-011 УГТ-путь, T-012 запросы/документы/комментарии/решения, T-013 регистрация 5 шагов, T-014 responsive+a11y pass.
P1: T-101 поддержка, T-102 конкурсы/пилоты, T-103 карта экосистемы, T-104 инвестэкспертиза, T-105 события/образование, T-106 ИС/НИОКТР, T-107 аналитика, T-108–111 воркспейсы науч.организаций/инвесторов/экспертов/производителей.
P2: T-201 matching, T-202 сохранённые поиски, T-203 чат, T-204 live-интеграции, T-205 экспорты, T-206 карта-слои, T-207 совместное ревью.

## 8. Риски

1. Нет реальных данных по технологиям/запросам/пилотам → качество empty-состояний критично; маркировка фикстур обязательна (риск «фальшивой экосистемы»).
2. Дрейф токенов между тикетами → имена токенов зафиксированы в T-001; все тикеты ссылаются на единый файл `globals.css`.
3. Next 16 dev: `127.0.0.1` — cross-origin → браузерный QA только на `http://localhost:3000`.
4. Длинные русские названия НИОКТР → проверка переносов на карточках и в таблицах.
5. Контраст в трёх темах → значения AA зашиты в токены T-001.
6. Субагенты упираются в лимит вызовов → родитель перепрогоняет гейты и коммитит (паттерн волн из технозрелость-скилла).
7. FOUC при переключении тем → inline-скрипт в `layout.tsx` до рендера.

## 9. Критерии приёмки (Design.md §18 + DoD брифа)

- Все маршруты ROUTES.md имеют осмысленный экран или осознанный редирект.
- Три темы: одинаковые семантика/статусы/a11y, разные визуальные миры.
- Публичное / кабинеты / операционный центр визуально различны.
- Работают «Найти решение» и «Представить технологию».
- Технологии, запросы, партнёры, НИОКТР — реальные данные или честные empty-состояния.
- Technology dossier работает в трёх режимах (public/participant/operations).
- УГТ: текущий уровень, доказательства, checkpoint, следующее действие.
- Нет повторяющихся синих карточек, uppercase-monospace-ярлыков, декоративных grid/glow.
- Формы сохраняют ввод; статусы и решения понятны.
- Мобильные сценарии работают; критические действия не на hover.
- Подключение бэкенда = замена адаптера без переписывания UI.

## 10. Границы интеграции

- Адаптер — единственная граница. После приёмки: mapping методов на `/api/v1` (auth, projects/registry, nioktr, executors, requests, stages, manager, files, notifications), маппинг статусов бэкенда на STATES.md, NextAuth-сессия, чек-лист DATA-CONTRACTS §6.
- В P0 реальный адаптер может существовать кодом, но НЕ подключён по умолчанию.
- Текущий фронтенд и бэкенд не модифицируются.

## 11. Допущения (приняты по документации, не по интервью)

1. `platform/` в worktree `new-front` — место контура; ветка `new-front` пушится в origin.
2. Упоминание `/workspace/technologies/:id` в ROUTES.md «Route conventions» — опечатка; канон — таблицы инвентаря (`/app/partner/technologies/:id`).
3. Фикстуры состояний — только с `isFixture: true` и видимой маркировкой; публичные реестры их не показывают.
4. Mock-авторизация в P0 (демо-роли); NextAuth — на интеграции.
5. Реальные данные P0: НИОКТР (sample 400 карточек). Иных реальных записей в бэкенде для публичного показа нет (демо-проекты бэкенда — синтетические dev-фикстуры, не публикуются).
6. Иконки — lucide-react (единое семейство, stroke 2, оптический размер по токенам).
7. Шрифт: Golos Text/Display (или системный эквивалент) + IBM Plex Mono только для ID/кодов/метаданных.
