# T-003 — Authenticated shells (sidebar + contextual top bar)

Status: done
Blocked by: T-001

## Цель
Ролевые авторизованные каркасы: `/(app)` — sidebar + контекстный top bar для участников; `/(operations)` — плотный операционный каркас Центра. Роли имеют РАЗНЫЕ приоритеты навигации (не один горизонтальный меню-бар).

## Зависимости
T-001 (токены). Использует роли из `src/lib/roles.ts` (см. ниже). Зависит от T-004 для реальных данных воркспейса, но каркас строится на честных состояниях.

## Изменяемые файлы / области
- `platform/src/app/(app)/layout.tsx` — sidebar (248–280px), top bar (раздел/хлебные крошки, поиск, уведомления, тема, профиль), мобильный drawer.
- `platform/src/app/(operations)/layout.tsx` — операционный каркас: очередь-first, плотная композиция.
- `platform/src/lib/roles.ts` — роли и приоритеты разделов (зеркало бэкенда): gk_customer, rd_executor, scientific_org, serial_manufacturer, regulating_organization, auditor, investor, cntr_admin, cntr_manager.
- `platform/src/components/sidebar.tsx`, `top-bar.tsx`, `notification-bell.tsx` (entry; контент — T-012), `profile-menu.tsx`, `mobile-drawer.tsx`.
- Общие разделы: Workspace, Мои проекты/назначено, Уведомления, Документы, Профиль и организация.

## Сценарий пользователя
Заказчик входит → видит приоритет: запросы, поиск решений, пилоты, шорт-листы. Исполнитель → технологии, заявки, запросы заказчиков, доказательства, пилоты. Сотрудник Центра → операционный центр, очередь проверки, реестр технологий, решения/аудит. Никто не пробирается через плоский список из 15 пунктов.

## Acceptance criteria
- [ ] Три роли P0 имеют различимые навигационные приоритеты; остальные роли — правдоподобный sidebar по ROLES.md.
- [ ] Sidebar масштабируется (модули добавляются без переделки).
- [ ] Текущий маршрут и следующее действие всегда видны.
- [ ] Ролевые ограничения отражены честно (нет доступа → permission-состояние, не «404 пустота»).
- [ ] Мобильный drawer + компактная полоса текущего раздела.
- [ ] Различие визуальной плотности: кабинеты инструментальные, операции плотные.

## Состояния
Sidebar/top bar работают при loading/empty/error страниц; неподписанный доступ к `/(app)` → редирект на `/login` (mock-сессия, T-013).

## Desktop / mobile
Desktop: sidebar 248–280px, контент max-width 1440px. Mobile: drawer, top bar с текущим разделом, уведомления доступны без hover.

## Данные и adapter requirements
`getWorkspace(role)` (T-004) — снапшот воркспейса. Без данных: пустые состояния «У вашей организации пока нет запросов» и т.п. (STATES.md §3).

## Критерии визуальной проверки
Браузер: вход под тремя демо-ролями (mock-сессия через UI-переключатель ролей, реализуется в этом тикете как временный dev-инструмент), скриншоты кабинетов в 3 темах, mobile-проверка drawer, lint/tsc/build зелёные.
