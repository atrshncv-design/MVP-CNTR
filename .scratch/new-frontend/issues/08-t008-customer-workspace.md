# T-008 — Customer workspace (кабинет заказчика)

Status: ready-for-agent
Blocked by: T-003 (shell), T-004 (адаптер), T-005 (состояния)

## Цель
Кабинет заказчика: создать запрос, получить совпадения, сравнить, шорт-лист, инициировать пилот, отслеживать документы/решения. Приоритет дашборда по ROLES.md: срочные задачи → активные запросы/пилоты → свежие проверенные технологии → шорт-листы → профиль/документы.

## Зависимости
T-003, T-004, T-005.

## Изменяемые файлы / области
- `platform/src/app/(app)/customer/page.tsx` — дашборд (рабочая очередь важнее декоративных KPI-карточек).
- `platform/src/app/(app)/customer/requests/page.tsx`, `requests/new/page.tsx` (форма: проблема, ограничения, отрасль, контекст внедрения, желаемый результат — прогрессивное раскрытие, сохранение черновика), `requests/[id]/page.tsx` (dossier запроса: статус, совпадения, документы, решения).
- `platform/src/app/(app)/customer/search/page.tsx` — поиск решений (реестр-вид, T-006-компоненты).
- `platform/src/app/(app)/customer/shortlists/page.tsx` — сравнение и шорт-листы.
- `platform/src/app/(app)/customer/pilots/page.tsx`, `pilots/[id]/page.tsx` — пилоты (entry-состояние).
- `platform/src/components/customer/` — `request-form.tsx` (прогресс, сохранение), `request-card.tsx`, `match-list.tsx`, `shortlist.tsx`, `compare-view.tsx`.

## Сценарий пользователя
Заказчик описывает проблему → форма сохраняет черновик → запрос создан («Что дальше: ожидайте проверку/совпадения») → видит совпадения с проверенными технологиями (фикстуры, помеченные) или честное «совпадений пока нет» → добавляет в шорт-лист → запрашивает уточнение или инициирует пилот → отслеживает решения.

## Acceptance criteria
- [ ] Создание запроса: пошаговая форма с сохранением ввода (назад/вперёд не теряет данные), field-level валидация с объяснением.
- [ ] Сравнение доступных доказательств и УГТ.
- [ ] Нет совпадений → честный следующий шаг («уточните запрос», «позже появятся»), не фейковые совпадения.
- [ ] Каждый статус запроса по STATES.md; следующий шаг виден.
- [ ] Пилот — entry-состояние с объяснением механики.

## Состояния
draft, under_review, clarification, active, closed, archived; пустой кабинет «У вашей организации пока нет запросов»; permission для чужих объектов.

## Desktop / mobile
Desktop: очередь + правая колонка контекста. Mobile: статус и следующее действие над сгибом, формы пошаговые, таблицы → стек-карточки.

## Данные и adapter requirements
`listCustomerRequests`, `getCustomerRequest(id, scope)`, `saveDraft`, `submitForReview`, `addComment` — фикстуры isFixture для демо-сценариев; публичные/недоступные — честные состояния.

## Критерии визуальной проверки
Браузер: полный сценарий «создать запрос → сохранить → вернуться → подать»; пустой кабинет; 3 темы; mobile; скриншоты. lint/tsc/build зелёные.
