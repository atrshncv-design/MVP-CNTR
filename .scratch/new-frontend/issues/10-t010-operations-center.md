# T-010 — Center operations center (операционный центр сотрудника)

Status: done
Blocked by: T-003 (operations shell), T-004 (адаптер+фикстуры задач), T-005 (состояния), T-007 (проверочный dossier)

## Цель
Операционный центр: приоритизированная очередь, table/queue/dossier-виды, назначение, сроки, недостающие доказательства, кандидаты на публикацию, история решений, аналитика по реальным записям. Очередь — главный объект, не меню.

## Зависимости
T-003, T-004, T-005, T-007.

## Сценарий пользователя
Сотрудник открывает центр → видит следующую задачу без сканирования меню → открывает объект (dossier/запрос/организацию) → назначает/берёт задачу → проверяет поля и доказательства → принимает решение с причиной → уведомление участнику → видит запись в истории решений.

## Acceptance criteria
- [ ] Следующая задача находится без лишних кликов; каждый элемент очереди ведёт к объекту и действию.
- [ ] Одобрение/уточнение/отклонение/публикация/архив трассируемы: actor, дата/время, решение, причина, следующий шаг, видимость.
- [ ] Отклонение и уточнение требуют причину; одобрение/публикация — подтверждение.
- [ ] Счётчики и аналитика — по реальным данным или отсутствуют.
- [ ] Таблица/очередь/dossier-виды работают; kanban опционален.
- [ ] Очередь пуста → «Очередь пуста» + время последнего обновления.

## Состояния
Все канонические статусы STATES.md; пустая очередь; permission (роли менеджера/админа); stale-уведомления.

## Desktop / mobile
Desktop: плотная таблица. Mobile: стек-карточки с подписями полей, решение доступно без hover, статус и срок над сгибом.

## Данные и adapter requirements
`getOperationsQueue(QueueQuery)` — фикстуры isFixture с полным набором статусов и сроков; счётчики только реальные; `recordDecision(DecisionInput)`.

## Критерии визуальной проверки
Браузер: очередь с задачами, принятие решения (причина обязательна), пустая очередь, история решений, 3 темы, mobile, скриншоты. lint/tsc/build зелёные.
