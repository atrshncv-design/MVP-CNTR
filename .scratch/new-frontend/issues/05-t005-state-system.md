# T-005 — Universal state system

Status: done
Blocked by: T-001

## Цель
Единая система состояний экрана и канонических статусов: loading/empty/error/permission/success/stale/archived + статусный словарь STATES.md. Один компонентный набор состояний для всех P0-страниц.

## Зависимости
T-001. Используется всеми тикетами T-006…T-014.

## Изменяемые файлы / области
- `platform/src/lib/status.ts` — канонические статусы (draft, action_required, under_review, clarification, approval, approved, rejected, published, active, blocked, archived, closed) + русские подписи строго по STATES.md §1 + маппинг на токены тем (success/warning/danger/info/neutral).
- `platform/src/lib/ugt.ts` — УГТ: band (low 1–3 / medium 4–6 / high 7–9), подписи уровней, «текущий уровень ≠ переход N→N+1».
- `platform/src/components/states/` — `loading-skeleton.tsx`, `empty-state.tsx` (объяснение + следующее действие), `error-state.tsx` (что сломалось, retry, fallback-маршрут, ввод пользователя сохраняется), `permission-state.tsx`, `success-state.tsx`, `stale-notice.tsx` (timestamp), `archived-state.tsx`, `save-in-progress.tsx`.
- `platform/src/components/status-badge.tsx`, `ugt-badge.tsx` — статус/УГТ с числом+подписью+формой (не только цвет).
- `platform/src/components/decision-timeline.tsx` — история решений: actor, дата/время, решение, причина, связанное доказательство, следующее действие, видимость (STATES.md §4).
- `platform/src/components/upload-state.tsx` — состояния загрузки документа (STATES.md §6): выбрано/загружается/сканируется/принято/отклонено/ошибка+retry/удалено из черновика/отправлено и зафиксировано. «Принято» — только после завершения валидации (mock).

## Сценарий пользователя
Любая P0-страница: при загрузке — структурированный скелет (не фейковый счётчик), при пустоте — объяснение и действие, при ошибке — retry без потери ввода, при отсутствии прав — понятное объяснение и путь запроса доступа, при успехе — подтверждение и следующий шаг.

## Acceptance criteria
- [ ] Каждый P0 data-маршрут покрывает: loading, empty, error, success; permission — где применимо; stale — где данные имеют timestamp.
- [ ] Подписи статусов = STATES.md (никаких синонимов «В работе/Активно/Процесс» как взаимозаменяемых).
- [ ] УГТ: число + название уровня + band + дата верификации + сводка доказательств + следующий checkpoint + текстовое объяснение.
- [ ] Отклонение и уточнение требуют причины; одобрение и публикация — шаг подтверждения.
- [ ] Семантика состояний одинакова во всех трёх темах и ролях.
- [ ] Комментарии контекстные (объект: технология/запрос/документ/checkpoint/решение), не полноценный чат.

## Состояния
Этот тикет и есть система состояний — все перечисленные выше.

## Desktop / mobile
Скелеты/пустые/ошибки адаптивны; действия пустых состояний — тач-цели ≥44px; состояние не скрыто за hover.

## Данные и adapter requirements
Статусы маппятся на STATES.md; адаптер возвращает типизированные результаты, из которых состояния строятся. Mock-адаптер умеет отдавать error/empty по требованию (триггер-параметр или отдельный dev-метод).

## Критерии визуальной проверки
Демо-страница `/dev/states` (временно, dev-only): все состояния + все статусы в 3 темах, desktop/mobile, скриншоты. lint/tsc/build зелёные.
