# T-012 — Requests, documents, comments, decisions

Status: done
Blocked by: T-005 (status/upload/decision-компоненты), T-008/T-009/T-010 (интеграция в кабинеты)

## Цель
Сквозные механики: документы (workspace `/app/documents` + upload-состояния), контекстные комментарии, уведомления, история решений, запрос уточнения, подтверждения одобрения/отклонения.

## Зависимости
T-005 (готовые примитивы: upload-state, decision-timeline, notification), T-008–T-010 (точки встраивания).

## Изменяемые файлы / области
- `platform/src/app/app/documents/page.tsx` — документный workspace организации.
- `platform/src/app/app/notifications/page.tsx` — центр уведомлений (объект, событие, срочность, требуемое действие, срок, прочитано/нет, прямой переход).
- `platform/src/components/comments.tsx` — контекстные комментарии (принадлежат объекту: технология/запрос/документ/checkpoint/решение; не чат).
- `platform/src/components/notifications/notification-item.tsx`, `notification-bell.tsx` (контент).
- Интеграция `decision-timeline`, `upload-state`, `status-badge` в dossier'ы и кабинеты.

## Сценарий пользователя
Исполнитель получает уведомление «Нужны уточнения по технологии N» → переходит к объекту → читает комментарий проверяющего → отвечает → прикладывает документ (видит честные состояния загрузки) → подаёт → сотрудник принимает решение с причиной → уведомление → история решений видна с полным контекстом.

## Acceptance criteria
- [ ] Каждое решение: причина, actor, время, следующее действие; видимость (публичная сводка/своя/полный аудит) по ROLES.md.
- [ ] Документы: явные состояния обработки (STATES.md §6); «принято» только после завершения валидации.
- [ ] Комментарии привязаны к правильному объекту; полноценный чат в P0 не требуется.
- [ ] Уведомления: объект, событие, срочность, действие, срок, прочитано/нет, переход.
- [ ] Отклонение/уточнение без причины невозможны; одобрение/публикация с подтверждением.

## Состояния
upload: выбрано/загружается/сканируется/принято/отклонено/ошибка/удалено/зафиксировано; комментарии; уведомления read/unread; решения approved/rejected/clarification/published/archived.

## Desktop / mobile
Desktop: документы списком/таблицей, комментарии рядом с объектом. Mobile: уведомления и решения доступны (важно: 3-й приоритет мобильных сценариев Design.md §8.3); загрузка документов работает.

## Данные и adapter requirements
`saveDraft`, `submitForReview`, `addComment`, `recordDecision` — фикстуры isFixture; уведомления — из фикстур событий (не фейковые таймстемпы «сейчас», а помеченные).

## Критерии визуальной проверки
Браузер: полный цикл «уточнение → ответ → решение» с историей; центр уведомлений; документный workspace с upload-состояниями; 3 темы; mobile; скриншоты. lint/tsc/build зелёные.
