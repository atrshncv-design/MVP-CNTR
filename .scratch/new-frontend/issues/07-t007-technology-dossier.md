# T-007 — Technology dossier (три режима)

Status: done
Blocked by: T-001, T-003 (шеллы), T-004 (данные), T-005 (состояния)

## Цель
Главный объект платформы — technology dossier — в трёх режимах: публичный паспорт `/technology/:id`, рабочий dossier участника `/app/partner/technologies/:id`, проверочный dossier сотрудника `/operations/technology/:id`. Один объект, ролевые представления.

## Зависимости
T-003, T-004 (фикстуры dossier), T-005, T-006 (карточка→dossier).

## Изменяемые файлы / области
- `platform/src/app/(public)/technology/[id]/page.tsx` — публичный паспорт (Design.md §5.2: заголовок+статус проверки, проблема/решение, области применения, текущий УГТ и путь, 4 измерения, сводка доказательств/публичные документы, организация, пилоты/история внедрения, связанные записи, контакт/заявка).
- `platform/src/app/app/partner/technologies/[id]/page.tsx` — рабочий dossier (редактируемые поля, документы, checkpoint'ы, комментарии, история подач, N→N+1).
- `platform/src/app/operations/technology/[id]/page.tsx` — проверочный dossier (очередь, назначенный проверяющий, внутренние заметки, история решений, публикация, аудит, флаги конфликтов/недостающих доказательств).
- `platform/src/components/dossier/` — `dossier-header.tsx`, `dossier-problem-solution.tsx`, `dossier-ugt-summary.tsx`, `dossier-dimensions.tsx` (радар — ДОПОЛНИТЕЛЬНО к текстовой разбивке), `dossier-evidence.tsx`, `dossier-organization.tsx`, `dossier-related.tsx`, `dossier-decisions.tsx`, `dossier-visibility.tsx`.
- `platform/src/lib/dossier-views.ts` — сборка представления по (объект, роль, scope).

## Сценарий пользователя
Посетитель: открыл технологию из реестра → паспорт с УГТ, доказательствами и действием «Подать заявку». Исполнитель: редактирует поля, видит checkpoint и недостающие доказательства. Сотрудник Центра: назначает проверку, запрашивает уточнение, публикует — с историей решений.

## Acceptance criteria
- [ ] Один объект — ролевые представления; публичный вид НИКОГДА не показывает внутренние комментарии и неопубликованные решения.
- [ ] Dossier объясняет: текущий уровень, доказательства, следующее действие.
- [ ] Публичный dossier при отсутствии реальных данных — честное состояние «Запись не опубликована/проходит проверку» (а НЕ фикстура).
- [ ] Радар 4 измерений сопровождается текстовой разбивкой и действиями.
- [ ] Частичные данные без выдумок.
- [ ] Связанные: запросы, исследования (реальные НИОКТР), партнёры, пилоты — по реальным связям или пусто.

## Состояния
verified / pending publication / unavailable; draft/under_review/clarification/approved/rejected/published (для участника и Центра); отсутствие прав — permission-состояние.

## Desktop / mobile
Desktop: dossier-композиция (левая колонка — содержание, правая — УГТ/действия). Mobile: порядок «статус и следующее действие → содержимое», вкладки/аккордеоны, без горизонтального скролла.

## Данные и adapter requirements
`getTechnology(id, scope)` — фикстуры с `isFixture: true` для кабинетов (статусы по STATES.md), публичный маршрут — пустое/недоступное состояние. Реальные НИОКТР-связи, если указаны в фикстуре, — только реальные id.

## Критерии визуальной проверки
Браузер: три режима dossier в 3 темах, desktop/mobile, скриншоты; проверка, что публичный режим не утекает (grep приватных полей в публичном рендере). lint/tsc/build зелёные.
