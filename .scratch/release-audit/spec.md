# Release-аудит существующего MVP

**Status:** ready-for-agent

## Problem Statement

Документация заявляет готовность многих функций, но требуется доказать сквозную работоспособность текущего frontend/backend и убрать мёртвые, моковые или незащищённые функции до расширения продукта.

## Solution

Построить фактическую матрицу UI → API → БД → RBAC → audit → tests, устранить найденные разрывы и зафиксировать проверенную базовую линию release candidate.

## User Stories

1. Как владелец, я хочу знать, какие функции действительно работают.
2. Как пользователь, я не хочу видеть мёртвые кнопки, фиктивные данные или ложный успех.
3. Как ревьюер, я хочу иметь повторяемый smoke/E2E набор для ядра УГТ.
4. Как разработчик, я хочу расширять только подтверждённое каноническое приложение.

## Implementation Decisions

- Аудит охватывает регистрацию, вход, девять ролей, проекты, приглашения, УГТ, документы, реестры, уведомления, менеджерские очереди и RAG.
- Неготовая функция либо доводится сквозно, либо скрывается, либо маркируется отдельным разделом «В разработке».
- Генерация документов скрывается/отключается и не считается готовой.
- Ошибки backend не превращаются frontend в успешное состояние.

## Testing Decisions

- Контрактные API-тесты, E2E основных ролей, визуальный smoke, IDOR-негативные тесты.
- Проверяется чистая база и повторяемый seed только для QA.

## Out of Scope

- Новые крупные модули из остальных пакетов.
- Полный редизайн внешних страниц.

## Further Notes

Результат — evidence-backed gap matrix и зелёная baseline-сборка.
