# D-04: Главная — живой первый экран и плотность контента

Blocked by: D-03 (RadarChart), D-06 (орнаменты)

Status: done

## Цель
Главная должна выглядеть ЖИВОЙ и плотной (вердикт: «вёрстка кривая», «разделы готов к наполнению на первом экране»). Возвращаем проверенные секции старого фронтенда в новой редакционной сетке + честные живые данные.

## Изменяемые файлы
- `platform/src/app/(public)/page.tsx` — главная.
- `platform/src/components/home/*` (новые: hero, steps, roles, levels, live-registry) — можно в одном-двух файлах.
- НЕ трогать: header (D-02), токены (D-01), компоненты кабинетов.

## Требования
1. **Hero (первый экран) = КОМБО (Q4)**: заголовок + два главных действия (Найти решение / Представить технологию) + справа РАДАР 4 измерений (RadarChart из D-03) + под ним МИНИ-ТРЕК пути УГТ (UgtTrack из D-07, компактный) + мини-счётчики: «400 исследований · 9 ролей · N технологий в проверке» (реальные числа из адаптера/фикстур).
2. **Убрать «Раздел готов к наполнению» с первого экрана**: блок «Сейчас на платформе» → живые ссылки на реестры с реальными счётчиками (listResearch → 400; технологии → честное «0 опубликовано, N на проверке» из фикстур; запросы → 0/честно).
3. **«Как это работает» — нумерованные шаги 01/02/03** (Экспресс-оценка → Верификация Центра → Рост N→N+1) в редакционной сетке, крупные цифры-номера.
4. **«Экосистема участников» — карточки ролей**: 9 ролей из `ROLE_META`/roles.ts, по одной строке «что делает» (тексты есть в ROLES.md — копировать оттуда, не выдумывать).
5. **«Что означает уровень» — компактный блок УГТ 1–9** (ссылки на /methodology/ugt) с цветовой семантикой шкалы (D-07): тёплые→холодные.
6. **Орнаменты (D-06)**: hero и разделители секций используют UdmurtOrnament/GeometryDivider в удмуртской теме; в светлой/тёмной — сдержанные геометрические разделители.
7. **«Последние верифицированные записи»**: вместо пустоты — реальные 3–5 карточек НИОКТР (listResearch, последние по дате) с provenance-бейджем.
8. Карта экосистемы остаётся честной («появится после подключения данных») — но в сжатом виде, не на первом экране.

## Acceptance
- Первый экран (1280×800) не содержит «готов к наполнению»; содержит hero+радар+действия.
- Секции шагов/ролей/уровней рендерятся без переполнения (scrollWidth ≤ clientWidth).
- Все тексты ролей — из ROLES.md, счётчики — из данных (не выдуманы).
- Гейты: lint/tsc/build; браузер :3001 (3 темы, desktop + 390px).

## Визуальная проверка
Скриншоты: главная в 3 темах, desktop и mobile; сравнить с референсом старой главной (плотность).
