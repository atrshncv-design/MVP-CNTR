# Единый внутренний frontend

**Status:** ready-for-agent

## Problem Statement

Внешние экраны обновлены, но внутренние кабинеты разнородны, частично дублируются и могут скрывать разрывы API или прав доступа.

## Solution

Создать единый защищённый shell и дизайн-систему для всех кабинетов, сохранив ролевые действия, реальный API и максимально широкую доступность современных устройств.

## User Stories

1. Как пользователь, я хочу единые навигацию, формы, статусы, ошибки и empty states.
2. Как пользователь, я хочу основные сценарии на телефоне, планшете и desktop.
3. Как пользователь клавиатуры или screen reader, я хочу доступные labels, focus и семантику.
4. Как менеджер/администратор/заказчик/исполнитель/эксперт, я хочу специализированные рабочие виджеты.
5. Как пользователь остальных ролей, я хочу узкое, но рабочее представление разрешённых данных.
6. Как пользователь, я хочу видеть честный beta/«В разработке» статус.

## Implementation Decisions

- Один dashboard shell; ролевые права и widgets вместо девяти независимых приложений.
- Полностью специализированы manager, cntr_admin, customer, executor/university и expert; остальные роли используют общие компоненты с узкими возможностями.
- Desktop/tablet полнофункциональны; mobile покрывает вход, профиль, оценку, проект, уведомления и простые решения.
- WCAG AA baseline, keyboard, focus, labels и reduced motion.
- Chrome/Edge latest-2, актуальные Firefox/Safari и Chromium-браузеры; старым небезопасным браузерам показывается понятное сообщение.
- Никаких mocks в release UI и никаких UI-only security checks.

## Testing Decisions

- Playwright E2E на реальном test API; responsive и accessibility smoke.
- Основная browser matrix и визуальные состояния ошибок/пустоты/загрузки.
- Снимки не заменяют поведенческие assertions.

## Out of Scope

- Полная оптимизация сложных admin-таблиц для маленького телефона.
- Новый редизайн внешнего лендинга.
- Поддержка Internet Explorer и произвольных embedded-браузеров.

## Further Notes

UI не меняет auth/RBAC ради удобства компонента; security-sensitive refactor требует отдельного тикета.
