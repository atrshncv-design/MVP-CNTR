# Чистый и однозначный репозиторий

**Status:** ready-for-agent

## Problem Statement

Репозиторий содержит конкурирующие деревья, старые экспорты, сборочные артефакты, локальные данные и долгоживущие ветки, из-за чего агент может редактировать неканоничный код или опубликовать лишние данные.

## Solution

Провести безопасную инвентаризацию, определить канонические frontend/backend, удалить подтверждённый мусор новым коммитом, усилить ignore-политику и подготовить понятное монорепо без переписывания истории, кроме отдельного случая обнаружения секрета.

## User Stories

1. Как разработчик, я хочу однозначно понимать, где находится актуальный код.
2. Как ревьюер, я хочу видеть в PR только относящиеся к тикету файлы.
3. Как владелец, я хочу знать, какие данные удаляются и можно ли их восстановить.
4. Как специалист по безопасности, я хочу обнаружить секреты во всей истории до публикации новых веток.

## Implementation Decisions

- Сначала read-only инвентаризация и классификация; удаление — отдельным подтверждённым коммитом.
- Каноническая структура: frontend, backend, infra, docs, tests, `.github/workflows`.
- Обычный мусор удаляется без rewrite истории. Rewrite допустим только после ротации найденного секрета и отдельного согласования.
- Ценные исторические материалы переносятся в `docs/archive`; сборки, cache, logs, `.env`, QA-БД и дубликаты не версионируются.
- Старые ветки не удаляются без отдельного подтверждения.

## Testing Decisions

- До и после очистки проверяются frontend build/lint/typecheck и backend tests/lint.
- Secret scan выполняется по working tree и полной истории.
- Проверяется воспроизводимость clone → setup → test без локальных незафиксированных файлов.

## Out of Scope

- Переписывание истории без найденного секрета.
- Удаление GitHub-веток.
- Изменение продуктовой логики.

## Further Notes

Очистка блокирует все остальные пакеты, потому что определяет канонические пути и безопасную базу ветвления.
