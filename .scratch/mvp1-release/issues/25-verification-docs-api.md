# 25 — API верифицирующих документов регулирующей организации

**What to build:** Роль «Регулирующая организация» (переименованный «Эксперт УГТ»): регистрируется, присоединяется к карточке проекта по join-токену TZ-XXXXXX (механика уже реализована в тикете 06 — переиспользуем), и **только после вступления** получает доступ к добавлению верифицирующих документов — «документ о подтверждении УГТ проекта». Документ попадает в очередь менеджера как подтверждающий материал (единый авторитет по УГТ — менеджер). Роль не монопольна: любой участник может загрузить такой документ сам.

**Blocked by:** 20, 22, 24 — Схема данных, очереди менеджера, реестры

**Status:** ready-for-agent

- [ ] `POST /api/v1/projects/{id}/verification-docs` — загрузка верифицирующего документа (файл, comment); RBAC: только активный участник проекта (в т.ч. регулирующая организация после join по токену)
- [ ] Документ сохраняется в `verification_documents` и появляется как материал в очереди менеджера (`GET /manager/queue/promotions` — блок «подтверждающие материалы»)
- [ ] До присоединения по токену регулирующая организация получает 403 на загрузку (доступ только после join)
- [ ] Любой участник (не только регулирующая организация) может загрузить верифицирующий документ — без ограничения по роли
- [ ] Тесты: регулирующая организация до/после join (403 → 200), обычный участник может загрузить, документ виден менеджеру в очереди
