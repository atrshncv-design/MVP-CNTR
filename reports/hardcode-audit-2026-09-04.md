- 84 файла с находками не содержат `useTranslations`/`getTranslations` вообще — перевод там невозможен архитектурно, а не «не доперевели пару ключей».

- Вынос: обернуть в `useTranslations`, ключи — в оба словаря; линт-гейт (см. §Гейт).

## План выноса (порядок)

1. **P0-1** экраны без словаря — волнами по фичам (project → registry → dashboard → landing), гейт на новые строки.
2. **P0-2** контентные данные + **P0-3** экспорт/реплики — теми же волнами, владельцы тех же файлов.
3. **P0-4** серверные тексты — коды ошибок + каталог сообщений; тексты готовности — в локализуемый источник.
4. **P1-1** адреса в конфиг/env; **P1-2** пометить непереводимое + тест поведения.
5. **P2** палитра в тему, дубли словарей убрать, язык логов.

## Гейт против накопления (правило для ревью/CI)

1. Новая кириллическая/латинская отображаемая строка в `*.tsx` вне `useTranslations`/`getTranslations` — ревью не проходит.
2. Новый внешний URL/хост/порт вне конфига/env — ревью не проходит.
3. Новый литерал текста в ответе API (`detail`/`message`/`raise`) — только через каталог сообщений/код ошибки.
4. Исключения с тестом поведения: списки ключевых слов (`sanitize`-тип), логи — помечаются комментарием `i18n:never` и не трогаются переводом.
5. Повторная проверка — одна команда (см. шапку), отчёт перезаписывается идемпотентно; расхождение counts — красный CI.

## Приложение: как сверять

- Полный перечень: `.autopilot/2026-09-04-hardcode-audit/evidence/findings.json` (каждая находка: файл, строка, категория, фрагмент).
